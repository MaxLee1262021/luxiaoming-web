# 商品管理功能设计方案

版本：V1.0 · 2026-11-03  
适用系统：麓小鸣旅拍管理后台及配套小程序  
交付范围：详细功能设计与离线可点击原型；本文中的新增能力均为设计目标，不代表已经接入后台、数据库或小程序。

配套原型：[商品管理可点击原型](ui/product-management-prototype.html)。原型使用合成示例，资料和操作结果仅保存在本地浏览器，不是生产商品。

## 1. 设计结论

新增统一的“商品管理”工作入口，统一查看照片留影、视频摄像、旅拍套餐和影像周边，按商品类型复用现有编辑器。首期重点完善影像周边的商品档案、分类、展示规格、价格、素材、服务说明、点位关联和显隐操作。

周边继续采用“展示＋咨询客服”方式。按 2026-10-31 已确认的 Q13，本期列表和编辑页不加入库存、销量；展示规格不升级成 SKU。支付、收货地址、实物下单和物流由后续实物交易项目单独建设。

核心体验是让运营清楚回答：这是什么商品、用户看到什么、价格与交付如何说明、为什么没有展示、隐藏后影响哪些套餐。

## 3. 导航与页面关系

建议在“内容运营”下以“商品管理”承接现有“商品上下架”入口，分四类标签：影像周边、照片留影、视频摄像、旅拍套餐；日常记忆用户上次选择，首次以影像周边进入。可再提供“全部类型”聚合视图。

现有“内容管理 → 影像周边”等入口先保留，进入同一编辑器和同一商品，不复制记录。原有 `shelfProducts` 路由键可保留兼容；是否改名或新增菜单由正式开发时的前后端路由目录与菜单授权共同完成。仅修改菜单文案不能自动授予权限。

```text
内容运营 / 商品管理
  ├─ 影像周边 → 周边列表 → 新建 / 编辑 / 手机预览
  ├─ 照片留影 → 统一摘要 → 现有照片编辑器
  ├─ 视频摄像 → 统一摘要 → 现有视频编辑器
  └─ 旅拍套餐 → 统一摘要 → 现有套餐编辑器

辅助入口：关联套餐 / 操作记录 / 回收站
```

统一商品管理负责查询和商品操作，不负责订单发货、支付、财务结算，也不替代小程序首页装修。首页推荐与排序仍以现有首页配置为准；商品开启显示后不保证自动进入首页推荐位。

## 4. 影像周边列表

### 4.1 信息与布局

页面标题“商品管理”，副说明“统一维护旅拍商品资料与小程序展示”。右上角为回收站、操作记录和蓝色主按钮“新建商品”。不使用营收或库存卡片作为装饰性指标。

| 区域 | 内容 |
| --- | --- |
| 商品类型 | 影像周边 / 照片留影 / 视频摄像 / 旅拍套餐；其它类型复用现有编辑器 |
| 状态标签 | 全部、显示中、手动隐藏、关联隐藏、草稿，随查询范围动态计数 |
| 常用筛选 | 名称或编号关键词、周边分类、实际展示状态 |
| 展开筛选 | 所属城市、关联打卡点、标签、仅后台使用 |
| 展示模式 | 表格 / 卡片，切换保留筛选与选中项 |
| 批量工具条 | 已选数量、批量显示、批量隐藏、取消选择 |
| 空状态 | 无商品可新建；无匹配结果可清空筛选，不能把二者混为一类 |

列表列建议按重要性排列：选择框、商品图和名称/编号、分类与规格、商品价格、交付周期、关联打卡点、展示状态及原因、关联套餐数、操作。更新时间作为次级文字或可选列，避免首屏过宽。

卡片保留现有商品图、分类、标签、名称、规格、价格和周期，补充显隐原因与操作。移动端使用卡片或纵向信息行，操作自然换行；不缩小字体挤满桌面表格。

以下名称与基础价格来自项目演示资料，其余规格、周期与文案用于演示设计，不是核验后的经营配置。

| 商品 | 分类 | 示例规格说明 | 展示价格 | 示例交付周期 |
| --- | --- | --- | --- | --- |
| 相册精装本 | 相册 | 8 寸 / 20 页 / 硬壳装订 | ¥129.00 | 选片确认后 7–10 个工作日 |
| 摆台相框 | 相框 | 6 寸 / 原木色 / 单面摆台 | ¥89.00 | 选片确认后 3–5 个工作日 |
| 明信片套装 | 明信片 | 10 张 / 哑光纸 / 长沙主题 | ¥59.00 | 确认后 3–5 个工作日 |

分类沿用相框、相册、冰箱贴、明信片、钥匙扣、其他。历史“照片打印”“相框装裱”等值保留并可筛选，运营可逐项调整，禁止自动批量归并导致错误分类。

### 4.3 状态规则

将“是否希望显示”与“现在能否公开展示”区分。界面用“显示/隐藏”，避免让“上架”暗示已支持线上购买。数据库仍可使用已有上架/下架枚举。

| 状态组 | 判定优先级 | 用户看到什么 | 可执行动作 |
| --- | --- | --- | --- |
| 草稿 | `status=草稿`，最高优先级 | 不公开 | 编辑、保存并显示、复制、超管删除 |
| 手动隐藏 | 非草稿，`isShow=false` 或其它手动禁用条件；`internalOnly=true` 归此组并显示原因 | 不公开 | 编辑、显示、复制、超管删除 |
| 关联隐藏 | 手动允许显示，但点位或其它依赖使实际不可见 | 不公开 | 查看原因、编辑关联、设为手动隐藏 |
| 显示中 | 手动允许且全部依赖允许公开 | 按小程序入口及城市范围展示 | 编辑、预览、隐藏、复制 |

同一条记录只归入一个状态组，状态计数合计等于当前类型的非回收记录数。状态标签计数应套用关键词、分类等非状态筛选；“全部”不包含回收站。隐藏原因可以有多条，不因状态分组丢失原因。

实际展示以服务端内容策略与公共查询过滤为准，管理界面不得自行将 `effectiveVisible` 持久化。`internalOnly` 必须同时关闭公开显示；对于历史字段冲突（例如 `enabled=false` 但 `isShow=true`）展示具体阻断原因，不用一个开关覆盖全部事实。待审/驳回等遗留记录保留阻断状态及原因，不在新界面冒充审核通过。

点位恢复显示时，原先仅被联动隐藏的商品可恢复；手动隐藏商品保持隐藏。清空点位明确写入空关联，不能再从历史风格字段继承旧点位。单个周边至多一个打卡点，关联可以留空。

“保存并显示”遇到已隐藏点位时，保存显示意图，但反馈“资料已保存，仍因 ×× 打卡点隐藏而未展示”；不反馈“已显示”。列表提供“调整关联”入口。修改点位本身仍需现有点位编辑权限，商品管理不能绕过。

## 5. 新建与编辑周边

使用现有独立草稿模式。新建默认草稿且不公开；取消、关闭、返回不改变原商品。已有商品修改先保留在编辑副本，保存成功才替换列表。存在未保存修改时离开需提示，保存中禁用重复提交。

### 5.1 表单与字段

| 分区 | 字段/模型 | 规则 |
| --- | --- | --- |
| 基本信息 | `name` | 名称，必填，沿用 60 字输入限制 |
| 基本信息 | `category` / `cate` | 分类，建议填写；兼容旧分类别名和旧值 |
| 基本信息 | `specs: string[]` | 展示规格，可多项；去空、去重，支持清空；不生成 SKU 笛卡尔积 |
| 基本信息 | `tags: string[]` | 复用共享标签与自定义标签入库规则 |
| 图片与视频 | `cover` / `image`、`images`、`videos` | 上传、预览、设主图、移除；正式环境复用 OSS 上传与文件授权 |
| 定价 | `price` | 人民币单一展示价格，非负有限金额、最多 2 位小数；缺失显示“价格待确认”，不伪造 ¥0 |
| 服务说明 | `deliveryCycle` | 交付周期文字，建议注明起算点；不是自动履约时限 |
| 服务说明 | `retouchIncluded` / `editingIncluded` | 是否包含照片精修/视频精剪，布尔字段；不从标签猜测包含与否 |
| 商品说明 | `intro` / `description` | 材质、工艺、制作要求、选片确认及交付说明 |
| 关联配置 | `cityId`、`spotId` / `spotIds` | 城市沿用现有城市；点位可选且最多一个，已选点位时检查城市一致性 |
| 展示配置 | `isShow`、`status` | 存储手动展示意图，实际状态由依赖计算 |
| 展示配置 | `isNew` | 新品，与 `isHot` 热门独立，纠正当前误绑定 |
| 高级配置 | `internalOnly` | 仅后台使用时不公开；开启该项应明确解释并关闭公开意图 |
| 高级配置 | `storeProductId`、`storeProductPromotionLink` | 旧微信小店配置，仅兼容保存，不作为展示的必填条件或新的购买入口 |

清空主图与商品说明时，同步清空历史别名，避免旧内容重新出现；旧图集里的媒体对象按实际 URL 读取。规格和标签是数组，不把整个数组转成一个字符串保存。

新图上传可从图集指定主图；当前主图被删除后提示选择替代图，不能悄悄保留已移除主图。后台未保存草稿预览允许显示本地临时图；正式发布必须使用已完成上传的素材地址。现有素材大小、数量政策沿用最新确认项，不在本次设计凭空新增限制。

### 5.2 保存动作与校验

| 动作 | 验证与结果 |
| --- | --- |
| 保存草稿 | 至少填写名称；已填写的价格须合法；保存为 `status=草稿,isShow=false`，不会对外公开 |
| 保存修改 | 已有商品维持当前手动显示意图；执行现有基础字段校验和依赖重算；不得自动把隐藏商品打开 |
| 保存并显示 | 名称、合法非负价格、说明、至少一个有效图片/主图素材满足当前周边发布条件；写入显示意图，再报告实际展示结果 |
| 取消/返回 | 丢弃编辑副本；有改动时二次确认；原始记录不改变 |

分类、展示规格、标签和交付周期建议完善，但本期不擅自增加为强制发布项。首图作为清晰运营建议，不能与现有“有商品图片素材即可”的发布校验矛盾。

草稿是本次需补齐的操作闭环：已有数据策略认识“草稿”，但现有周边保存函数会统一改为上架/下架。正式实现必须调整保存动作，才能承诺刷新后仍保留草稿状态。已有显示商品点击“保存草稿”会使其隐藏，须提示影响；更推荐日常用“保存修改”。本期不承诺双版本草稿与线上版本并存。

### 5.3 手机预览

预览名称、分类、价格、全部展示规格、标签、图视频素材、商品说明、交付周期、精修/精剪；底部唯一业务动作是“咨询客服”。编辑时标记“未保存预览”，列表打开标记“已保存资料预览”。

对隐藏商品允许后台预览，但清楚标记“仅后台预览”；预览不是公开可访问性验证。预览中的客服动作仅演示提示，不发消息、不创建订单。

## 6. 商品操作与影响反馈

### 6.1 复制为草稿

生成新 ID，复制商品资料、分类、价格、素材引用、说明、展示规格、服务选项和点位；名称追加“副本”。重置草稿、隐藏、审核痕迹、创建修改时间；新品默认关闭。旧小店商品 ID 和推广链接默认不复制，防止两个本地商品误指同一个旧外部商品。不会复制日志、订单、销售或库存历史。

### 6.2 显示与隐藏

单条显示执行与表单一致的发布校验。隐藏前展示受影响套餐清单、数量及作用说明，允许继续隐藏，由既有策略联动套餐；不恢复已经废止的“必须先替换套餐才能隐藏”规则。隐藏不删除套餐明细，不改写历史订单。

批量操作先确认范围及影响，再逐项执行。结果至少区分“已显示”“已设显示但依赖阻断”“已隐藏”“校验失败”“权限/网络失败”。部分成功保留成功结果，只允许重试失败项；不能以一条成功提示掩盖整个批次失败。

跨分页选择默认只作用于明确勾选的记录，筛选变化清空不可见选择并告知，不默认为全库。草稿、仅后台使用与旧审核阻断记录不能被无提示批量发布。

### 6.3 删除与回收

只有超管可以删除。沿用现有“实际不可见后才允许删除”规则；显示中商品需先隐藏，因点位联动而实际不可见的商品也可删除。确认框给出关联套餐影响，随后软删除进入现有回收站，历史订单与售后继续保留。已确认规则允许删除，不因历史订单引用而阻断。

恢复先校验依赖是否存在，沿用既有恢复后手动隐藏的规则，避免旧内容突然公开。已删除点位不自动重建；存在该依赖时明确提示并要求调整。彻底删除继续使用现有回收站权限及确认机制，不从商品列表新增快捷入口。

### 6.4 记录与错误处理

记录商品类型与 ID、操作人、时间、操作、字段差异、前后手动状态及批次 ID。上传失败、保存失败都保留编辑副本，明确失败原因，不返回“已保存”。正式接入时若要阻止多人覆盖，需要单独设计版本号/更新时间条件校验；当前通用保存接口不能被假定已有并发冲突保护。

## 7. 权限设计

| 角色 | 列表/预览 | 新增编辑/复制 | 显示隐藏 | 删除/恢复 |
| --- | --- | --- | --- | --- |
| 系统超管 | 允许 | 允许 | 允许 | 允许，沿用状态前提 |
| 内容运营 | 有相应菜单授权时允许 | 沿用 `contentEdit` | 沿用内容操作授权 | 不允许删除；恢复按回收站权限执行 |
| 客服 | 默认无新增管理入口；订单内按已有范围读取商品 | 不允许 | 不允许 | 不允许 |
| 财务、摄影师、商家、分销/代理 | 沿用已有业务范围 | 不新增授权 | 不新增授权 | 不新增授权 |

菜单可见、按钮权限和服务端写入权限必须同时校验。原型角色切换只用于演示界面，不能作为真实鉴权机制。商品预览不得暴露文件私有读权限或管理接口凭据。

## 8. 数据与正式接入建议

### 8.1 数据源保持统一

| 类型 | 现有事实源 | 统一列表路由目标 |
| --- | --- | --- |
| 影像周边 | `peripherals` | 周边编辑器 |
| 照片留影 | `albums` | 照片编辑器 |
| 视频摄像 | `packages` 内视频单品 | 视频编辑器；复用 `isVideoSingle` 判别，不能仅按名称或 `type` 猜测 |
| 旅拍套餐 | `packages` 内组合套餐 | 套餐编辑器；排除视频单品 |

统一列表采用 `(collectionKey,id)` 复合标识，防止不同集合的同名 ID 冲突。`effectiveVisible/visibilityReasons`、被引用套餐数和类型文案属于查询投影，不写成第二套商品事实。

优先复用 `LXM_API`、`persistContentMutation`、内容校验、OSS 文件服务和回收站。正式开发前需核实 `isNew`、周期、精修/精剪及后台专用字段在当前 MySQL 明确列/扩展映射中的保存和回读，不假定 HTML 增加控件就能持久化。

保持已有公共 RPC `getPeripherals` 和小程序展示工具的职责。后台字段调整不能把库存、内部备注或管理投影扩散到公共接口。当前演示货架用整单金额匹配商品的算法不作为商品营收依据，本页不显示该统计。

需补齐的既有缺口：`internalOnly` 目前未被服务端 `ownContentVisible` 或 `isPublicPeripheral` 独立过滤，且保存归一化可能按 `isShow=true` 覆盖临时下架状态。正式接入必须在管理保存与公共查询同时强制“仅后台记录不可公开”，不能只靠前端把开关关闭来承诺隔离。原型演示的是修正后的设计行为。

### 8.2 建议的开发顺序

1. 整理统一列表查询投影、类型识别、状态分组与筛选；复用权限和现有菜单路由。
2. 补齐周边草稿保存、复制、显隐、失败反馈；纠正新品字段；验证旧字段清空与数据回读。
3. 增加关联套餐影响清单、批量逐项结果、软删恢复和日志；核实点位联动与城市筛选。
4. 对接其余三类编辑器，完成后台与小程序公共展示回归。

本次交付不执行上述业务改造，不运行真实数据库迁移，不发布上线。

### 8.3 后续实物交易边界

若后续要支持“立即购买”，单独评审默认 SKU/多 SKU、库存事务和预占流水、全款支付阶段、地址隐私、发货与签收、退款、订单快照。现有支付的 `deposit/final` 不等于已有实物 `full` 支付；规格文本不能直接充当可交易 SKU。

小程序目前禁止周边进入预约；服务端仍兼容部分历史拍摄＋周边组合。统一商品入口不扩大这一入口，历史订单继续按其保存快照读取。套餐包含周边也不等于已经支持实物履约。

| 编号 | 场景 | 预期 |
| --- | --- | --- |

| P12 | 批量显示包含无效资料/仅后台记录 | 逐项结果清晰；失败项可重试，无全成功假提示 |

| P20 | 小程序公共访问隐藏商品 | 以服务端过滤为准；不能仅靠管理页徽标判断成功 |

## 10. 原型使用与覆盖范围

双击配套 HTML 即可离线打开。可演示筛选、表格/卡片、周边新建与编辑、草稿和显示校验、手机预览、复制、批量显隐、超管删除与回收恢复。原型中已保存数据只影响当前浏览器的示例存储，使用“重置示例”可复原。

其它商品类型以只读摘要表达复用关系，不在此原型复制已有三个完整编辑器。原型实现本地图片上传与设主图，视频上传控件、完整图视频浏览及高级城市筛选留在正式开发范围。原型不提供真实登录、上传 OSS、客服发信、审批、订单和支付，正式接入及小程序真机验证仍按以上验收清单实施。
