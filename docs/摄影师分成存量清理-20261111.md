# 摄影师分成存量清理

根据回传表 PH-Q06、PH-Q07，本次支持一次性清除摄影师存量财务金额和历史冲抵余额，不回填这些历史报酬。新支付订单继续按现行协议比例计酬。

## 清理范围

脚本只选择以下摄影师财务记录，并在执行前生成精确快照和笔数、金额清单：

| 数据 | 归属判定 |
| --- | --- |
| `benefit_ledger` | `beneficiary_type='photo'` |
| `photo_settlement` | 摄影师对账单，包含草稿、已推送、已认可和已发放的存量记录 |
| `svc_adjust` | `plan_id` 有 `photo:` 前缀，或关联上述摄影师对账单，或人员明确属于摄影师且不与客服档案 ID 重叠 |
| `svc_notification` | 对应被清除账单/明细的 `photo_statement`、`photo_payment` 通知 |
| `lxm_reconciliationTransfers` | `objectType` 为 `photo/photographer/摄影/摄影师` |
| `lxm_adjustmentRecords` | `targetType` 为 `photo/photographer/摄影/摄影师` |
| 旧财务子记录 | 上述旧财务主记录关联的 `lxm_reconciliation_transfer_orders` 与 `lxm_collection_values` 行 |

保留摄影师档案、登录账号、合作协议编号、比例版本、订单履约、派单记录、客户信息、客服财务和商家财务。人员 ID 同时出现在摄影师与客服档案且无其他证据的调账会列为异常，脚本拒绝执行该快照，先核对其归属。

## 切换时刻与防止历史金额重新生成

切换时间使用带时区的明确时间，由生成快照时的 `--cutoff` 固定。它按支付时点划分新旧财务：支付时间小于或等于切换时间的订单，清理后不再生成摄影师分成；支付时间晚于切换时间的订单正常计酬。

因此，切换前已支付的在途订单仍可照常履约，但不再因后续完成、转派或重复回填重新产生已清除的摄影师存量金额。切换前下单但切换后才支付的订单仍按新业务处理。

清理与防重建标记在同一 MySQL 事务中提交。标记使用现有 `photo_profile_log`：`photo_id='*'`、`action='finance_reset'`，`detail` 记录版本、固定切换时刻、快照 SHA256 和本次清理编号。不新增业务表。该动作扩展档案日志字典，仅供一次性财务维护使用。普通运行逻辑只读取标记，不触发清理。

## 执行方式

下列命令在后台项目目录执行，数据库连接沿用 `.env` 的 `DB_*` 配置。脚本直接使用 mysql2 建立连接，不调用自动建表入口；`DB_AUTO_MIGRATE` 不会影响本脚本。

1. 只读盘点：

   ```text
   node scripts/cleanup-photo-share.cjs
   ```

   返回清理表、记录数、分值金额、异常 ID 和既有标记。数据库结构未安装时，返回 `ready:false` 与缺失表名，不把未知金额当成零，不创建缺失表。

2. 固定切换时刻并生成仓库外快照，例如：

   ```text
   node scripts/cleanup-photo-share.cjs --cutoff 2026-11-11T16:00:00+08:00 --snapshot D:/受限备份/photo-finance-before-reset.json
   ```

   请将示例时间替换为实际切换时刻。快照包含被清除财务行的原始字段、数据库来源摘要和校验值，可用于恢复。文件和 `.sha256` 旁文件均拒绝覆盖；路径及目录实际目标必须位于代码仓库外。快照可能包含客户 OpenID、收款凭证地址等信息，应放在有适当访问权限的本地备份目录，不纳入代码提交。

3. 核对清单、快照与 SHA256 后执行：

   ```text
   node scripts/cleanup-photo-share.cjs --apply --snapshot D:/受限备份/photo-finance-before-reset.json --expect-sha256 此处填写已核对的64位SHA256 --operator 实际操作人账号
   ```

   执行时获取与客服/摄影师业务共用的 `svc_runtime_lock`，重新核对数据库来源及每条选中记录。快照生成后金额、记录、归属或通知状态有变化，会在任何删除发生前拒绝执行。每条删除按准确主键定位；全部删除与清理标记同事务提交，任一失败整体回滚。相同快照重复执行仅返回已执行结果，不会清除新产生的金额；不允许用另一份新快照反复清零。

   切换前应停止业务写入和通知投递并安排维护窗口，以便快照稳定、避免外部通知刚送达而清单仍显示待发。存在 `sending` 通知时拒绝生成清理快照，等待投递状态落定后重新盘点。脚本没有给其他财务表做清零的入口。

## 恢复

可以由原始快照生成恢复 SQL，生成操作不连接数据库：

```text
node scripts/cleanup-photo-share.cjs --snapshot D:/受限备份/photo-finance-before-reset.json --expect-sha256 已核对SHA256 --restore-sql D:/受限备份/photo-finance-restore.sql
```

恢复 SQL 使用事务、原始字段和主键插入，在恢复行后移除该快照对应的防重建标记。它不使用覆盖现有行的 `REPLACE` 或 `ON DUPLICATE KEY UPDATE`；主键冲突会报错，避免覆盖切换后的真实业务。恢复前须暂停写入和通知 worker、核对数据库来源及是否已有后续业务，再审查并人工执行 SQL。脚本不会自动执行恢复 SQL。
