# 总工作台企微联系接入

本能力仅供新增总工作台使用，保留原企微发链、商品外链、员工邀请及旧工作台联系方式。服务端准备的是客户端会话调用信息，不发送消息，也不宣称客户已收到消息。

## 官方支持的调用方式

使用企业微信自建应用的 JS-SDK `openEnterpriseChat`，传入单个已映射的 `externalUserIds`，由当前客服在企业微信客户端中打开与客人的会话。当前版本使用官方 `wecom-jssdk-2.4.0.js`、应用身份注册、企业签名和应用签名。

普通外部浏览器无法通过此客户端 JSAPI 直接打开外部联系人会话。官方“打开个人聊天窗口 schema”的 `get_launch_code` 仅支持企业内部成员，因此本实现不会拼接未经支持的 `wxwork://...` 外部联系人地址。

官方依据（核对日期 2026-11-20）：

- [开始使用 JS-SDK](https://developer.work.weixin.qq.com/document/path/90514)：官方 CDN、`ww.register`、应用身份注册、可信域名及客户端时序。
- [打开会话](https://developer.work.weixin.qq.com/document/path/92525)：`openEnterpriseChat` 的外部联系人参数与单聊形式。
- [JS-SDK 签名算法](https://developer.work.weixin.qq.com/document/path/90506)：服务端签名、URL 去除 `#` 及两种票据的获取/缓存。
- [获取客户详情](https://developer.work.weixin.qq.com/document/path/92114)：自建应用须配置为客户联系可调用应用，使用 `follow_user` 核对当前客服关系，超出500个跟进人时分页。
- [打开个人聊天窗口 schema](https://developer.work.weixin.qq.com/document/path/94345)：仅企业内部成员，不能作为外部联系人的普通浏览器降级。

## 服务端接入边界

建议路由：`POST /api/kf/orders/{order_no}/contact`。路由必须先校验总工作台菜单、现有订单可见范围与角色/操作权限，再读取可信的订单及当前登录客服映射，调用：

```js
const contact = createSvcGeneralContact({ env: process.env });
await contact.prepare({
  order: authorizedOrder,
  staff: { wecom_userid: currentOperatorWecomId, staff_status: 'active' },
  pageUrl: body.pageUrl,
  userAgent: request.headers['user-agent'],
});
```

`staff` 必须是当前登录操作人的企微成员，不能用订单归属客服替代。客户端提供的 `staff_id`、`external_userid`、手机号等不得直接用于指定联系对象。模块还通过官方 `externalcontact/get` 核对当前成员是否实际添加该客户。

返回 `kind=wecom_jsapi`、`status=ready_to_open`，带 `corp_id`、`agent_id`、`config_signature`、`agent_signature` 和单个 `params.externalUserIds`。客户端点击时加载官方 SDK，使用 `ww.register` 注册企业/应用身份，再执行 `ww.openEnterpriseChat(params)`；仅客户端成功回调可显示“已打开会话”。取消和失败如实显示，不能显示“消息已送达”。

仅允许为服务端配置的 HTTPS origin 签名。票据和 Secret 不下发；手机号、客户备注和供应商原始响应不进入返回值或错误对象。

## 必要的外部配置

配置放在部署环境或仓库外的环境文件，不把实际 Secret 或客户映射提交到代码库。

| 环境项 | 用途 |
| --- | --- |
| `WECOM_GENERAL_CONTACT_ENABLED` | 显式设为 `true` 才启用；默认不启用 |
| `WECOM_CORP_ID` | 目标企业 ID，复用企业标识；不复用通讯录同步 Secret |
| `WECOM_GENERAL_CONTACT_AGENT_ID` | 企业微信自建应用 ID |
| `WECOM_GENERAL_CONTACT_SECRET` | 该自建应用的 Secret，应用须获准调用客户联系接口 |
| `WECOM_GENERAL_CONTACT_ORIGINS` | 逗号分隔的精确 HTTPS origin，例如 `https://admin.example.test`；须同时在企微配置并验证可信域名 |
| `WECOM_GENERAL_CONTACT_TIMEOUT_MS` | 准备调用超时，默认10000毫秒，允许1000～30000毫秒 |
| `WECOM_GENERAL_CONTACT_CUSTOMERS_JSON` | 可选：服务端保存的 `customer_openid → external_userid` 对象映射 |

客户映射优先读取已授权订单的 `wecom_external_userid`、`wecomExternalUserId`、`customerExternalUserId` 或 `external_userid`；缺失时才读取上述服务端 JSON 映射。小程序 `openid`、手机号、姓名都不是企业微信 `external_userid`，不能相互替代。不要按手机号猜测联系对象。

如果生产订单读投影尚未携带已维护的外部联系人字段，可用仓库外的 JSON 映射接通；后续接入已有可信客户映射源时，应保持路由先鉴权及模块关系复核。需要当前客服的有效企微成员映射、已添加的外部联系人关系、应用可见范围、服务器可信IP、已验证的应用可信域名及企业微信客户端。仅配置员工通讯录自动邀请不满足这些条件。

## 验证及限制

单元测试使用注入的模拟官方响应，验证两种签名、当前客服关系、分页、凭证缓存/刷新、源限制、错误清洗及未发送消息，不触发真实联系或邀请。生产联调须由已配置的客服在企业微信应用内打开已授权订单，验证客户端实际打开会话；缺少凭据、客户映射或客户端时应展示明确错误，不能以测试通过声称生产通路已联通。
