## 二、推荐启用的标准专家（WorkBuddy）

> 左侧栏「专家」→ 浏览分类 → 按名称启用。以下为对应标准角色：

1. **后端开发工程师（Node / 全栈）**
   - 负责：真实后端 api.cjs、MySQL 自托管、写接口鉴权、多门店架构、角色双源清理。
   - 与 UI Designer 的接口面：`lxmApi` 约定的 `/api/collection/{name}` 读写契约。
2. **云架构 / DevOps 专家**
   - 负责：CLOUDBASE 密钥配置（如需）、生产部署、环境隔离、禁用 cloud 模式下的稳定性。
3. **数据分析 / 财务对账专家**
   - 负责：月度对账口径、财务报表、退款/收款审核的财务规则定义。
4. **测试 / QA 专家**
   - 负责：端到端「后台改→小程序读」验证、回归测试。
5. **产品经理 / 业务专家**
   - 负责：短视频套餐是否合并、商家多门店业务规则等决策，并输出给后端落地。

## 三、实施方案（分阶段）

### 阶段一 · UI Designer 主导（现在可开工，不依赖其他专家）
1. **A 收尾**：把三栏范式复制到其余 11 个内容视图（套餐/周边/短视频单品/打卡点/城市/风格/素材库/标签/上下架/商品审核/小程序装修/攻略）。
   - ⚠️ 前置决策：短视频套餐「合并 or 保留现状」需你拍板（见第四节）。
2. **B 美化**：其余模块纯视觉升级（基于 `tokens.css`，逻辑不动）。
3. **财务审核页 UI 打磨**：`audit.html` 视觉升级（逻辑不动）。

### 阶段二 · 后端 / 云专家主导（可与阶段一并行）
- 真实后端生产化（MySQL 自托管、鉴权、健壮性）。
- 多门店商家架构、角色权限双源清理。
- 由产品专家拍板的业务变更（如短视频合并）落地。

### 阶段三 · 联合验证（测试专家）
- 端到端「后台改 → 小程序读」联调；回归全部模块。
