# 已支付订单认领入口修复

触发场景：订单承接页的订单已真实支付、状态为待认领、无客服归属，也没有有效复购预占，但因 `svc_paid_processed=0` 且没有客服支付事件记录，只显示“详情”。本次以用户截图中的订单条件复核，确认支付事实存在。

已修正为：全部订单、公共待认领池、工作台待办使用一致的认领候选条件。客服主动点击“认领”时，在事务中写归属、待确认状态及认领操作日志；随后“我的订单”和跟进页通过该日志识别接入事实，刷新及重启后继续可操作。按原支付时点取比例，已有明细快照保留；缺少对应历史比例时明确报错并整体回滚。

认领不会伪造支付事件、修改支付时间或回放复购预占。未支付、已归属、有效预占和非待认领状态继续禁止认领。未记录客服归属的旧待拍订单显示“未记录客服归属”，不再误标“公共池”，也不回退状态。

即使自动支付接入尚未启用，已手动认领订单的观察期、提醒、结算及退款处理仍按现有规则运行；其他订单不因此自动接入。服务通过只读的认领日志存在性查询判定，不扫描订单回放支付。旧订单操作接口同样识别手动接入事实，拒绝绕过客服工作台修改。

本次未代用户认领截图中的真实订单，未改本机启用配置。真实订单只读复核确认修复后的 `can_claim=true`。

验证：全量1228项，1209通过、19按环境条件跳过、0失败；浏览器完成“已支付无事件标记 → 显示认领 → 点击后移出公共池 → 我的订单可继续确认时间”；并发认领、SQL重读、原比例快照、手动接入后台任务及旧接口保护均有回归覆盖。语法和静态构建检查通过。
