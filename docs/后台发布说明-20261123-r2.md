# 后台查询与内存优化 · 20261123-r2

本版按架构评审落实兼容优化：保留现有业务规则、返回字段、权限与操作流程，减少文件元信息重复读取、MySQL 文档还原中间对象、实物纯读路径的全库快照和写锁等待。

## 改动

- 通用 MySQL `list` 分批还原并释放每批关系中间数据；`listMany` 限制排队的读取批次，保留全集、SQL 顺序、关联及 EAV 覆盖语义。
- 新增位置对齐的 `getMany(key, ids)`，主表和关系均保留原单条 `get` 的等值比较语义。单批最多 100 个 ID，缺失为 null，重复结果相互隔离。
- 只读请求内合并文件元信息查询和重复描述；下一请求重新读库。授权、上传完成、绑定、订单同步和写入继续使用实时原数据源。
- 实物地址、订单列表/详情/计数及售后列表仅读取必要用户及关联事实，保留原投影、排序、分页和错误结果；纯读不持有 commerce 写互斥锁，也不对全库做深复制和差异写入。
- 目录、购物车、报价、支付、物流同步、库存操作及全部写入保留原事务。后台任务周期、金融补偿、账本规则和幂等约束保持原有行为。

## 部署与回退

本版没有数据库结构迁移、生产数据库参数或 Redis 配置变更。按现有更新脚本部署，保留服务器原 `.env`、凭据和证书。默认发布包不包含本机 `.env`、测试数据、测试库或原文件备份。

部署后检查应用健康、订单/售后/文件查询、实物地址和订单，再观察目标 API 的 P95/P99、Node RSS/堆和外部分配、数据库连接等待和任务积压；与相同业务流量对照。若需回退，使用更新脚本保留的上一个代码目录，数据合同保持兼容。

## 验证与适用范围

测试包含请求隔离、文件隐私和授权、缺失/重复/大小写/重音/历史关联 ID、EAV 覆盖、实物新旧读写对照和库存初始化等；另在独立本地 MySQL 上执行实际 SQL 和新旧完整响应对照。结果与测量方法随工作区交付记录提供。

该版本压缩重复 I/O 和中间结构内存。通用全集接口仍返回全集；实物列表仍保留原 JavaScript 排序/分页，当前用户自己的长历史仍可能增长。为保留旧影子索引列不一致时的业务语义，实物读取使用权威 JSON body，不能宣称已使用 owner 索引或获得恒定查询成本。数据库真分页、可信读投影及写事务/worker重构属于后续独立验证项。

隔离库和合成数据的性能结果不等同线上收益、MySQL 8.4 实例的实测结果或并发容量承诺。当前发布包仅为本地构建交付；实际部署须按项目发布流程执行。
