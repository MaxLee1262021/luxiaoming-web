# 商品规格与库存管理

2026-11-05：根据本次需求，使用原“影像周边”菜单作为“商品管理”，维护相框、相册等实物商品。继续使用 `peripherals` 路由、集合与原有内容编辑权限。此前设计方案中“不增加库存、不升级 SKU”的范围约定由本次需求更新。

## 管理内容

- 基本资料：商品名称、分类、商品编码、销售单位、标签、图片、视频、商品说明、点位关联与显示状态。
- 单规格：售价、展示规格、库存数量。
- 多规格：按行维护规格名称、SKU 编码、售价、库存；可增加和删除规格，最多 100 条。规格名称和已填写的 SKU 编码不允许重复。
- 销售参数：库存预警值、基础运费、交付周期。
- 列表：查看规格、售价、库存及未设置、缺货、预警、充足状态，支持库存状态筛选。

## 数据规则

`specMode` 为 `single` / `multiple`。多规格保存为 `skus: [{ skuCode, spec, price, stock }]`；商品 `specs` 从规格名称生成，`price` 为最低规格售价，`stock` 为各规格库存之和。`stockQty` 同步为兼容别名。库存与预警为非负整数，库存最大为 2147483647，金额按两位小数保存。

旧商品仍可读取 `stock` / `stockQty`，缺少库存时显示“未设置”；不会把缺失库存自动解释为真实的零库存。草稿独立编辑，保存成功后更新列表，失败保留草稿。

现有 MySQL 库存列和 typed leaf 存储继续承载销售参数与 SKU，无需新建业务表。管理 API 校验销售参数并返回库存；小程序公共接口沿用商品展示资料，过滤内部库存与编码。

## 本次范围
