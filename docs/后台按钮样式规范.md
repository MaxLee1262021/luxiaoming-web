# 麓小鸣旅拍管理后台 · 统一按钮样式规范

版本：V1.0 · 源码实施版\
日期：2026-10-26\
适用范围：当前 Web 管理后台，Vue 3 + Element Plus，浅色运营工作面。\
交付目的：供设计、前端与验收共同使用。已于 2026-10-26 接入当前后台源码，尚未部署；按钮统一入口为 `src/styles/buttons.css`。

配套文件：[可离线打开的按钮与业务场景示例](ui/后台按钮规范示例.html)。示例中的数据与操作均为演示。

## 1. 统一方向

**以蓝色承载主操作、绿色承载正向生效、橙色承载需注意的业务调整、红色承载危险或终止操作、灰色承载辅助操作。**

按钮首先回答“会发生什么”，其次回答“有多重要”。采用“操作语义 × 强调层级”的双维度体系：同一种删除操作始终是红色，但表格中用红色文字按钮，最终确认时用红色实底按钮。

本项目选择蓝色作为后台工作流主色，以便将高频的新增、保存、查询与危险动作明显区分。这是针对当前系统的设计决策，并非所有电商平台都必须使用蓝色。品牌红橙可继续用于品牌标识、导航与装饰；不再承担通用按钮的全部操作语义。

### 当前需要纠正的问题

| 现状 | 使用风险 | 统一要求 |
| --- | --- | --- |
| 主操作红橙与危险红接近 | 新增、保存与删除看起来同样危险 | 主操作蓝、危险红，建立稳定认知 |
| 主按钮、描边、文字按钮被多层 CSS 覆盖 | 不同页面同类按钮外观不同 | 一套按钮令牌、一套状态规则 |
| 部分文字按钮悬停变为实底白字 | 表格行出现突兀色块，层级跳变 | 文字按钮始终保持低强调，悬停仅加浅底与加深字色 |
| 同一停用操作出现红、橙两种颜色 | 用户难以判断可恢复性 | 可恢复停用统一橙色；删除账号为红色 |
| 部分批量上下架、审核没有稳定语义 | 批量与单条操作认知不一致 | 单条、批量和确认框沿用同一语义 |

## 2. 颜色标准

以下为本轮按钮专用标准色。背景均按不透明浅色工作面设计；不得直接复用到深色或透明玻璃面板。

| 语义 | 默认色 | 悬停深阶 | 按下深阶 | 浅底 | 典型操作 |
| --- | --- | --- | --- | --- | --- |
| 主操作 Primary | `#2563EB` | `#1D4ED8` | `#1E40AF` | `#EFF6FF` | 新增、保存、查询、编辑、分配、领取 |
| 正向 Success | `#15803D` | `#166534` | `#14532D` | `#F0FDF4` | 上架、启用、审核通过、恢复普通数据 |
| 注意 Warning | `#B45309` | `#92400E` | `#78350F` | `#FFFBEB` | 下架、停用、暂停、确认退款金额、封存账单 |
| 危险 Danger | `#DC2626` | `#B91C1C` | `#991B1B` | `#FEF2F2` | 删除、取消订单、关闭交易、驳回并终止申请 |
| 辅助 Neutral | 文字 `#374151` | 底 `#F3F4F6` | 底 `#E5E7EB` | 默认底 `#FFFFFF` | 重置、导出、刷新、取消编辑、关闭弹窗 |

中性按钮默认边框 `#8C95A3`，悬停及按下边框 `#6B7280`。通用禁用态：文字 `#9CA3AF`、底色 `#F3F4F6`、边框 `#D1D5DB`。

### 对比度与可读性

| 实底按钮 | 白字对比度，约值 |
| --- | --- |
| 蓝 `#2563EB` | 5.17:1 |
| 绿 `#15803D` | 5.02:1 |
| 橙 `#B45309` | 5.02:1 |
| 红 `#DC2626` | 4.83:1 |

以上数值按相对亮度公式计算。正常可操作的 14px 按钮文字应达到 4.5:1；禁用控件属于该对比度条款的例外，但仍应可辨认。[W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

**危险描边／文字按钮的悬停必须使用深红字 `#B91C1C` 配浅红底 `#FEF2F2`，约 5.91:1。** 原红 `#DC2626` 直接配该浅红底约 4.41:1，不可作为正常小字号文字组合。其他语义也统一在悬停、按下时采用相应深阶字色。

## 3. 强调层级

| 层级 | 外观 | 使用位置 | 示例 |
| --- | --- | --- | --- |
| 高强调：实底 | 语义色实底＋白字，无渐变 | 当前操作组的主要提交或最终确认 | 保存修改、确认上架、确认删除 |
| 中强调：描边 | 白底＋语义色字＋1px 同色边框 | 工具栏次操作、批量动作、详情页操作 | 批量上架、暂停服务、确认退款金额 |
| 低强调：文字 | 透明底、无可见边框、语义色字 | 表格行、紧凑详情内操作 | 查看、编辑、下架、删除 |
| 中性辅助 | 白底灰字灰边；低强调时透明底灰字 | 返回、导出、重置、关闭 | 取消编辑、暂不删除 |

- 同一操作组最多一个高强调按钮。最终确认上架时可以是绿色实底；最终删除时可以是红色实底，其余按钮降低强调。
- 页面主工具栏、筛选区、弹窗提交区是不同的操作组，不要求整页只存在一个实底按钮。
- 表格行操作默认全部使用文字按钮。不要为每行的查看、上架、下架、删除分别铺设实底色块。
- 工具栏中的导出、刷新、预览使用中性按钮；表格中用于打开详情的“查看”使用蓝色文字按钮，便于识别信息入口。
- 按钮颜色由操作后果决定，不能由操作人角色、文件类型、所属菜单或当前记录状态决定。
- “已支付、已上架、已完成”等结果使用标签或状态文字，不做成可点击按钮。按钮写动作“上架”，状态写结果“已上架”。

上述强调规则参考 [Ant Design 按钮设计原则](https://ant.design/docs/spec/buttons/)，具体语义色与业务映射以本规范为准。

## 4. 按钮尺寸与布局

| 规格 | 可见高度 | 字号／字重 | 水平内边距 | 使用场景 |
| --- | --- | --- | --- | --- |
| 紧凑 Small | 32px | 14px／500 | 12px | 表格行、紧凑工具栏、局部操作 |
| 标准 Default | 36px | 14px／500 | 16px | 筛选、表单、抽屉、弹窗 |
| 大号 Large | 40px | 14px／500 | 20px | 登录、少量关键页面入口 |
| 触控 Touch | 至少 44px | 14px／500 | 至少 16px | 手机和平板的有效点击区域 |

统一几何规则：

- 圆角 **6px**，边框 **1px**；实底与描边保持相同盒模型，切换状态不改变尺寸。
- 同组间距 **8px**；危险按钮与普通操作之间建议 **12px**；区块间距 **16–24px**。
- 默认无投影、无渐变、无悬停上移、无缩放。颜色过渡 **120ms**；减少动态效果设置下关闭非必要动效。
- 两字、四字按钮不使用人为拉开的字距；禁用 Element Plus 的两字自动加空格行为，统一按自然文案宽度布局。
- 常规按钮内容宽度自适应；提交区可统一最小宽度 **80px**。文字按钮不强制 80px，避免表格操作列过宽。
- 图标 **16px**、图文间距 **6px**。只有刷新、展开等明确动作可用纯图标；必须具备可访问名称与提示。
- 桌面文字按钮的点击区域至少 **32px 高、24px 宽**；触控区域扩展为至少 **44×44px**，相邻区域不得重叠。
- 同一操作组使用同一高度。不要以更大字号或更大圆角替代强调层级。

44×44px 是本项目的触控推荐值；WCAG 2.2 AA 的目标尺寸基线为 24×24 CSS px，并有间距等例外，二者不要混淆。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

### 排序规则

| 位置 | 从左到右 |
| --- | --- |
| 筛选区 | 查询（蓝实底） → 重置（中性）；高级筛选单列为辅助操作 |
| 页面工具栏 | 新增（蓝实底） → 导入／导出等中性辅助操作 |
| 表格操作列 | 查看／编辑（蓝文字） → 对当前记录的业务动作 → 更多／危险动作末位 |
| 普通弹窗底部 | 取消（中性） → 保存／提交（语义实底），整体右对齐 |
| 危险确认框 | 暂不删除／返回（中性） → 确认删除等（红实底），整体右对齐 |
| 批量工具栏 | 已选数量 → 批量正向／调整动作 → 批量危险动作；零选中时禁用相关动作 |

行内直接露出的动作原则上不超过 3 个，其余收入“更多”。危险动作即使放在“更多”中，也保持红字，并在执行前确认。窄屏先换行或改为纵向分组，不压缩按钮文字、不让底部按钮超出屏幕。

## 5. 完整交互状态

| 状态 | 实底按钮 | 描边按钮 | 文字按钮 |
| --- | --- | --- | --- |
| 默认 | 默认语义色底／白字 | 白底／默认语义色字与边框 | 透明底／默认语义色字 |
| 悬停 Hover | 悬停深阶底／白字 | 语义浅底／悬停深阶字与边框 | 语义浅底／悬停深阶字 |
| 按下 Active | 按下深阶底／白字 | 语义浅底／按下深阶字与边框 | 语义浅底／按下深阶字 |
| 键盘焦点 Focus-visible | 保留当前层级，额外显示清晰焦点环 | 同左 | 同左 |
| 禁用 Disabled | 统一禁用灰，不保留鲜艳语义色 | 同左 | 灰字、透明底，不显示可操作悬停反馈 |
| 加载 Loading | 保留语义、显示进度图形和“保存中…”等动作文字 | 同左 | 仅适用于局部轻操作；长任务改用明确进度反馈 |

- 焦点环采用 `2px solid #2563EB`、`outline-offset: 2px`；不要用 `outline: none` 清除且不补替代样式。焦点不得被容器裁切或底部固定条遮挡。[W3C 焦点可见说明](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)
- `disabled` 及 `loading` 时阻止鼠标、键盘和程序路径的重复提交；禁用规则优先于 hover／active。
- 加载保留按钮占位与原操作组布局；可按最长加载文案预留宽度。失败后解除加载、保留表单和错误原因，允许明确重试。
- 正式业务必须等待接口成功才提示成功；例图中的计时加载仅用于展示。
- 权限不足通常隐藏用户不可执行的操作；业务条件不满足则禁用并说明原因，如“请选择至少 1 条订单”。不要只用悬停提示承载必要原因，应有邻近可见说明或可聚焦的说明入口。
- 操作成功后更新结果状态，避免保留“上架”与“已上架”矛盾的可执行动作。

## 6. 各业务场景的操作映射

以下“蓝／绿／橙／红”代表语义；所在位置再决定采用实底、描边或文字形式。

| 业务场景 | 操作 | 语义与建议层级 | 判定依据 |
| --- | --- | --- | --- |
| 通用筛选 | 查询／搜索 | 蓝实底 | 当前筛选组的主要执行动作 |
| 通用筛选 | 重置／展开筛选／清空勾选 | 中性描边或文字 | 只调整本地视图或选中状态 |
| 通用工具栏 | 新增／新建 | 蓝实底 | 创建入口 |
| 通用工具栏 | 导入／上传 | 蓝描边或中性描边 | 普通数据处理；文件为图片或视频不改变颜色 |
| 通用工具栏 | 导出／下载／刷新／预览 | 中性描边 | 辅助阅读或获取数据 |
| 通用表单 | 保存／提交／确认修改 | 蓝实底 | 普通表单写入 |
| 通用表单 | 取消编辑／返回／关闭窗口 | 中性描边 | 退出当前界面，不终止业务 |
| 列表详情 | 查看／编辑／设置 | 蓝文字 | 进入信息或编辑界面 |
| 商品运营 | 上架／批量上架 | 绿文字；批量绿描边；最终确认绿实底 | 正向生效 |
| 商品运营 | 下架／批量下架 | 橙文字或描边 | 商品暂时不可售，可恢复 |
| 商品运营 | 设为主推／配置推荐 | 蓝文字或描边 | 普通运营设置 |
| 商品运营 | 取消主推／移除推荐位 | 中性文字 | 仅移除推荐关系，不删除商品 |
| 内容审核 | 审核通过 | 绿文字；审核确认区绿实底 | 正向审核结果 |
| 内容审核 | 退回补充／要求修改 | 橙文字或描边 | 返回上一环节，仍允许补充 |
| 内容审核 | 驳回并终止申请 | 红文字；最终确认红实底 | 否定并终止当前申请 |
| 订单履约 | 领取／接单／首次安排拍摄 | 蓝文字或描边 | 开始或推进工作流，不代表处理完成 |
| 订单履约 | 未确认阶段调整日期／人员 | 蓝文字或描边 | 普通信息调整 |
| 订单履约 | 修改已确认档期／转派已派任务 | 橙文字或描边 | 影响既定履约安排，需说明影响 |
| 订单履约 | 上传成片／查看交付 | 蓝或中性，按所在操作组定层级 | 上传或查阅，不等于订单完成 |
| 订单履约 | 同步支付状态／查询支付结果 | 蓝文字或描边 | 查询服务端事实，不手动确认到账 |
| 订单履约 | 取消订单／关闭交易 | 红文字；最终确认红实底 | 终止客户业务 |
| 售后 | 发起售后／提交退款申请 | 蓝描边或实底 | 提交申请本身不执行资金退回 |
| 售后 | 确认退款金额 | 橙描边或实底 | 核对并锁定金额，送后续审核 |
| 售后 | 查看凭证／打开凭据登记表 | 蓝文字 | 进入信息或填写界面 |
| 售后 | 确认登记退款结果 | 橙实底 | 修改资金处理记录；明确只是登记 |
| 售后／财务 | 审核通过／确认已登记结果 | 绿文字或实底 | 审核结论；不得伪装成执行退款 |
| 售后 | 处理完成 | 绿文字或实底 | 完结售后事项，不手动完成支付订单 |
| 财务 | 确认打款登记／封存账单／复核封存 | 橙描边或实底 | 财务结果登记或锁定，需核对 |
| 财务 | 解封财务账单／解除财务锁定 | 红文字或描边；最终确认红实底 | 重新开放已锁定财务数据，不按普通“启用”处理 |
| 权限／渠道 | 授权／修改角色／新增人员 | 蓝 | 普通管理流程，必要时另列影响说明 |
| 权限／渠道 | 启用人员／启用角色 | 绿文字或描边 | 恢复可用 |
| 权限／渠道 | 停用人员／停用角色 | 橙文字或描边 | 可恢复的访问限制 |
| 回收站 | 恢复普通数据 | 绿文字或描边 | 撤销普通软删除 |
| 回收站 | 永久删除／清空回收站 | 红文字或描边；最终确认红实底 | 不可逆的数据销毁 |
| 异常处理 | 无法履约并退回重派 | 橙 | 不取消客户订单，只调整履约 |
| 异常处理 | 强制状态回退／解除风控与财务锁定 | 红 | 影响受保护状态或限制，需权限与留痕 |

### 金额与支付的边界

当前后台的“确认退款金额、登记凭证、财务审核”不等于系统向支付渠道执行退款，不能在示例中合并成一个“确认退款”动作。

若未来系统增加真正执行资金退回的能力，**实际执行退款的最终确认**采用红实底，写明退款金额、对象、渠道和后果；这是扩展规则，不代表当前已实现该能力。

当前订单完成由服务端确认尾款到账后触发。不得为了按钮统一新增“手动完成订单”或“手动确认到账”。原有绿色“已完成／已支付”继续作为状态展示。业务依据见 [最新订单流程与迁移](最新订单流程与迁移.md) 及当前 `src/app/06-orders.js`。

## 7. 确认、文案与交互安全

### 文案

- 使用明确动宾短语：“新增商品、保存修改、确认下架、取消订单、永久删除”。
- 轻量、上下文明确的表格操作可写“查看、编辑、上架、下架、删除”。
- 不使用单字“删”、模糊的“确定操作”，不以感叹号或全红文字制造层级。
- 表单中的“取消”是退出编辑；取消交易必须完整写“取消订单／关闭交易”。
- 财务登记按钮写“登记退款结果／确认登记”，不得写成“立即退款”造成能力误解。

### 危险确认框

标题与确认按钮使用同一动作，明确显示操作对象、数量及后果。例如：

> 标题：永久删除这 3 条记录？\
> 正文：记录“演示商品 A”等将永久删除，删除后无法恢复。\
> 左侧按钮：暂不删除（中性）\
> 右侧按钮：永久删除 3 条（红实底）

取消订单的确认框应写明对履约和支付记录的实际影响，不宣称“自动退款”，除非接口确实执行该行为。可恢复的软删除应明确写“移入回收站”，与永久删除区分。

- 高风险确认初始焦点落在取消按钮或说明区域；不要让普通 Enter 意外触发不可逆操作。
- 真正模态弹窗应限制焦点于弹窗内，Esc 关闭后归还触发按钮焦点；未保存内容需要退出确认时保持一致规则。
- 金额、删除对象和数量应来自最终确认时的真实数据；异常或失效后提示重新核对。
- 批量操作展示已选数量及受影响范围；部分成功时说明成功与失败项，不只给“操作成功”。
- 普通保存、刷新、导出不逐一增加二次确认；仅按真实后果决定是否需要确认。

## 8. 开发接入要求

### 8.1 令牌隔离

建议新增按钮专用的 `--lxm-action-*` 令牌，使操作语义与品牌装饰解耦。不要直接把所有 `--lxm-brand-*` 改成蓝色，否则导航、图表、推荐位与品牌标识会同时被误改。

```css
/* 按钮令牌摘要；完整运行实现见 src/styles/buttons.css。 */
:root {
  --lxm-action-primary: #2563eb;
  --lxm-action-primary-hover: #1d4ed8;
  --lxm-action-primary-active: #1e40af;
  --lxm-action-primary-soft: #eff6ff;
  --lxm-action-success: #15803d;
  --lxm-action-success-hover: #166534;
  --lxm-action-success-active: #14532d;
  --lxm-action-success-soft: #f0fdf4;
  --lxm-action-warning: #b45309;
  --lxm-action-warning-hover: #92400e;
  --lxm-action-warning-active: #78350f;
  --lxm-action-warning-soft: #fffbeb;
  --lxm-action-danger: #dc2626;
  --lxm-action-danger-hover: #b91c1c;
  --lxm-action-danger-active: #991b1b;
  --lxm-action-danger-soft: #fef2f2;
  --lxm-action-neutral: #374151;
  --lxm-action-border: #8c95a3;
  --lxm-action-radius: 6px;
  --lxm-action-height: 36px;
}
```

常规按钮将语义 `type` 与 `plain/link` 分开：

```html
<el-button type="primary" :auto-insert-space="false">新增商品</el-button>
<el-button :auto-insert-space="false">导出</el-button>
<el-button type="primary" link>查看</el-button>
<el-button type="primary" link>编辑</el-button>
<el-button type="success" plain>批量上架</el-button>
<el-button type="warning" link>下架</el-button>
<el-button type="danger" link>删除</el-button>
```

`info` 不作为新增的彩色动作类型；普通辅助操作使用不指定 `type` 的中性按钮。不要依靠运行时匹配按钮文字来自动涂色。操作语义应由业务配置或显式 props 指定，避免“取消编辑”与“取消订单”误匹配。

Element Plus 提供 `type`、`plain`、`link`、`loading`、`disabled` 等属性；本规范的 32/36/40px 高度需要由统一按钮样式映射，不能假定与其默认尺寸一致。[Element Plus Button](https://element-plus.org/en-US/component/button)

### 8.2 弹窗独立指定确认按钮

MessageBox 的 `type: 'warning'` 负责消息图标，不等同于危险确认按钮已变红。须显式设置 `confirmButtonClass` 或在统一封装中按语义指定；原生按钮、弹窗传送至 body 后的节点也须纳入覆盖。

```js
// 接入示例：只呈现确认框，不在示例中执行删除。
await ElementPlus.ElMessageBox.confirm(
  '演示商品将移入回收站，可在回收站恢复。',
  '将演示商品移入回收站？',
  {
    type: 'warning',
    confirmButtonText: '移入回收站',
    cancelButtonText: '暂不删除',
    confirmButtonClass: 'el-button--danger lxm-action-confirm--danger',
    cancelButtonClass: 'lxm-action-cancel',
    autofocus: false
  }
);
// 统一封装还需在弹窗打开后安排安全焦点，并在关闭后还原焦点。
```

给确认按钮增加 danger 类时需检查默认 primary 类是否仍在，避免两个类型的 CSS 同时竞争；集中样式应让显式确认语义优先。消息框配置依据：[Element Plus MessageBox](https://element-plus.org/en-US/component/message-box)。

### 8.3 当前样式覆盖顺序

当前入口同时加载 `styles.css → tokens.css → enhancements.css → admin-content.css → lxm-pro.css → lxm-polish.css → glass-theme.css → admin-ops.css → upload.css → buttons.css`。路由会将页面样式插入 `data-admin-ops` 标记之前，统一按钮层保持在后；页面不再单独定义按钮语义色。

接入时应集中替换／收敛按钮相关规则，覆盖默认、plain、link、text、disabled、loading 和 Teleport 弹窗。不要继续在每个页面追加 `!important` 补丁。特别核查旧规则对 `.el-button--primary > span` 的强制白字；否则蓝色文字／描边按钮仍可能出现白字。

原生 `<button>` 与 `<el-button>` 的业务动作应消费同一套令牌。菜单、分页、筛选标签、Tab、卡片选择器属于各自组件，不要因标签也是 button 就一并改成操作按钮。

## 9. 验收清单

1. 同一操作在所有页面、批量入口与确认框中具有相同语义。
2. 新增／保存为蓝，删除／取消订单为红；不再共享红橙主色。
3. 上架绿、下架橙；启用绿、停用橙；审核通过绿，退回补充橙，终止性驳回红。
4. 表格行操作为文字按钮，悬停不突然变成白字实底；无按钮字号跳变、位移或阴影漂移。
5. 同组最多一个高强调动作，危险动作末位；单条与批量操作均显示明确作用对象。
6. 所有语义的默认、悬停、按下、禁用、加载、焦点状态可辨认，文字在实际背景上达到规定对比度。
7. 禁用与加载状态不能通过鼠标、键盘重复触发；失败后可重新操作且保留输入。
8. 普通弹窗按“取消 → 提交”、危险确认按“返回 → 危险确认”排列；焦点可见且正确归还。
9. 320px 窄屏、桌面与触控尺寸下均无操作区横向溢出、文字裁切和点击区域重叠。
10. 纯图标按钮有可访问名称；关键操作与必要解释不依赖颜色或悬停独自传达。
11. 退款申请、金额核对、结果登记、审核与实际出款明确区分；不引入当前系统不存在的支付能力。
12. 订单完成仍由服务端到账事实触发；状态标签不伪装成操作按钮。
13. 新按钮样式不误改菜单、分页、Tab、图表、品牌标识或小程序前台。
14. 代表性页面至少验收：商品上下架、订单列表与详情、售后金额确认、财务审核与封存、人员权限、回收站及删除确认框。
