# 小程序微信支付接入

本服务使用微信支付 API v3 的 JSAPI/小程序支付链路。小程序只负责调用 `wx.requestPayment`；金额、下单签名、支付结果确认和订单状态更新都在服务端完成。

## 部署前配置

在部署平台的密钥管理或服务器 `.env` 中配置以下项目，禁止提交私钥、APIv3 密钥或证书文件：

| 配置 | 用途 |
| --- | --- |
| `WX_APP_ID` / `WX_APP_SECRET` | 小程序登录，换取用户 openid。 |
| `WECHAT_PAY_MCH_ID` | 微信支付商户号。 |
| `WECHAT_PAY_APP_ID` | 付款小程序 AppID；必须与 `WX_APP_ID` 相同。 |
| `WECHAT_PAY_MCH_SERIAL_NO` | 商户 API 证书序列号。 |
| `WECHAT_PAY_MCH_PRIVATE_KEY_PATH` | `apiclient_key.pem` 的服务器绝对路径；也可通过 `WECHAT_PAY_MCH_PRIVATE_KEY` 注入 PEM。 |
| `WECHAT_PAY_API_V3_KEY` | 32 字节 APIv3 密钥，用于解密回调。 |
| `WECHAT_PAY_NOTIFY_URL` | 外网可访问的 HTTPS 回调，例如 `https://api.example.com/api/payments/wechat/notify`。 |
| `WECHAT_PAY_PLATFORM_PUBLIC_KEY_ID` 与 `WECHAT_PAY_PLATFORM_PUBLIC_KEY_PATH` | 微信支付公钥和 ID，用于验证接口响应与回调。也可改用平台证书序列号和路径。 |
| `WECHAT_PAY_PLATFORM_VERIFIERS` | 证书轮换期的 JSON 数组，保留旧、新 serial 对应的公钥或证书，服务会按 `Wechatpay-Serial` 选择验签材料。 |

商户平台必须将该小程序 AppID 与商户号绑定。回调地址不能带查询字符串，并需能在公网 HTTPS 下由微信支付访问。

平台验签材料切换前，先将新公钥/证书与旧材料同时写入 `WECHAT_PAY_PLATFORM_VERIFIERS` 并重启服务；确认不再收到旧 serial 后再移除旧项。反向代理必须将 `/api/payments/wechat/notify` 的请求体和 `Wechatpay-*` 请求头原样转发。

## 数据库迁移

部署前先完成备份，并在维护窗口执行：

```powershell
npm run migrate:mysql -- --apply
```

迁移会为 `lxm_order_payment_records` 补齐 `out_trade_no`、`prepay_id`、交易状态等字段及唯一索引，并创建独立的预约支付草稿及其支付索引表。正式订单与预约支付草稿必须同时具备持久化能力，才能在服务重启后安全续付或处理支付回调。

## 支付链路

1. 定金：`createBooking` 保存独立预约支付信息，尚不创建正式订单。尾款：已预约订单进入服务端允许支付尾款的拍摄阶段。
2. `createPayment` 从预约支付信息或订单快照计算金额，以 `out_trade_no` 创建 API v3 JSAPI 预支付单。
3. 后端返回 `timeStamp`、`nonceStr`、`package`、`signType`、`paySign`；小程序调用 `wx.requestPayment`。
4. `/api/payments/wechat/notify` 使用原始请求体验签并用 APIv3 密钥解密通知，逐项校验商户号、AppID、openid、金额和商户订单号。
5. 只有已验签的 `SUCCESS` 通知或已验签查单结果才会将支付流水改为已确认。定金到账后幂等创建“已预约”正式订单；尾款到账后完成原订单。重复通知按微信交易号幂等处理。

预支付参数临近两小时有效期、或创建预支付单后服务异常导致参数未保存时，服务会先验签查单；未支付交易会被关单并将旧记录标记失败，客户可重新发起支付，不会永久卡在“支付中”。

## `requestPayment` 返回 `errno: 102`

`requestPayment:fail access denied`、`jsapi has no permission`、`banned` 或“支付功能暂时无法使用”属于微信侧支付权限拒绝，不是订单状态或支付回调代码可以解除的错误。微信支付官方文档将 `errno: 102` 定义为小程序支付权限被公众平台限制。

排查时要单独查看商户平台「账户中心 → 经营场景管理」中该 AppID 的场景状态。即使订单发货管理已接入、交易结算授权已确认、商户号关联状态正常，**未发布的小程序仍只允许测试额度**；官方规则为每月测试额度 10000 元，三个月后将无法收款，发布后才能申请解除限额。若场景页没有显示限额、且公众平台通知中心也没有说明，应保留客户端日志中的 AppID、`envVersion`、版本号和 `errno`，向微信支付/公众平台支持提交核查；服务端不能通过重试或修改支付参数绕过该限制。

小程序的 `requestPayment` 成功回调不直接创建或修改订单；它只刷新服务端支付状态。预约表单必须取得服务端确认与正式订单标识后才跳转成功页。取消支付、支付失败或结果确认中不会生成待支付订单；支付通知遗漏或延迟时，预约表单或尾款订单页查询会向微信支付查单补偿。

## 预约支付接口（2026-10-16）

| RPC | 请求与返回 |
| --- | --- |
| `createBooking` / `createOrder` | 请求仍包含摄影项目、联系人、意向日期/时段、须知版本及幂等键。需要定金时返回 `bookingId`、`bookingStatus: pending_payment`、`paymentRequired: true`、`depositDue`、`totalAmount`，不返回正式 `orderId`。 |
| `createPayment` / `createPaymentIntent` | 定金传 `bookingId`、`phase: deposit` 和支付幂等键；后端计算金额并返回微信预支付参数。尾款继续传正式 `orderId`。 |
| `getPaymentStatus` | 定金传 `bookingId`、`phase: deposit`。支付到账并完成建单后返回 `bookingStatus: confirmed`、正式 `orderId`、`orderNo` 和公开订单投影。 |
| `cancelBooking` | 修改预约前传 `bookingId`。服务端确认未支付并安全关闭原交易后返回 `bookingStatus: cancelled`，客户端才清除旧支付标识并解锁表单；查到已支付则返回已确认的正式预约。查询或关单失败不释放原申请。 |

同一预约提交键、支付请求键和微信交易均需幂等。客户端重试时复用原预约和支付标识。免定金配置可直接返回已确认预约；不调用零元微信支付。`testPayment` 也支持 `bookingId`，仅用于隔离测试环境。

本次接口变更需要后端与小程序配套发布。旧客户端不能继续把 `createBooking.success` 理解为订单已创建，也不能把待确认支付跳转为预约成功。

## 验收

先运行本地回归：

```powershell
npm test
```

然后在微信支付商户平台和真实小程序体验版完成一次定金、一次尾款的支付验证，保留 API v3 请求 ID、微信交易单号、回调日志和订单流水作为验收证据。生产环境保持 `TEST_PAYMENT_ENABLED=false`，测试支付不能替代真实支付验收。
