# 鹿小鸣旅拍 · 管理后台系统整体设计方案（v1）

> 文档定位：**给你（非技术决策者）审阅的整体蓝图**。先讲清楚"专业旅拍后台到底要管什么"，再逐模块拆到功能/字段/交互，最后落到现有工程的对照与缺口、以及后台 UI 设计规范。你看完拍板，我们再一块块落地。
> 设计基准：微信小程序（C 端）+ 自托管网页后台（luxiaoming-admin）+ 企业微信（沟通与履约闭环）三件套；鹿小鸣=**自营履约**，文案禁用"派单平台/撮合/中介"等表述。

## 〇、一句话版结论（外行先读这段）

1. **你问的"商品、素材管理专业叫什么"**
   - **商品管理** = 在后台创建/上下架/定价"客人能预约购买的产品"，专业叫 **Product Management（商品中台/CMS）**。在旅拍行业具体就是：照片单品、短视频单品、旅拍套餐、影像周边、约拍定制。
   - **素材管理** = 管理照片/视频原始文件、样片、成片底片的库，专业叫 **数字资产管理 DAM（Digital Asset Management）/ 媒体资源库 / 样片库**。
2. **好消息**：你的后台工程（`luxiaoming-admin`）已经搭好了 **30 个页面路由**，覆盖了你要的 7 大块，还自带了运营看板、溯源、内容审核、系统日志这些专业后台的标配。所以**不是从零设计，是在骨架上补全做专业、做闭环**。
3. **一个修正**：你开头说的"6 处写死"里含"锁单费 ¥10"——它**已经按你的指令彻底删除了**，现在真实剩下的是 **5 处**（城市 / 隐私政策 / 搜索热词路线 / 约拍定价 / 预约须知），都属于"后台配了小程序读不到"的 RPC 联调缺口，本方案把它们单列在第六节，先放一边、不阻塞后台设计。

## 二、模块总览（七大区 + 现有 30 页对照）

现有 `src/router/index.js` 已定义的 30 个路由，按专业后台架构归并如下。**说明：你的 7 块需求 100% 被覆盖，且后台已自带运营/溯源/审核/系统四块专业标配。**

```
鹿小鸣管理后台
├─ A. 运营中心 operation/        【你未提，但专业后台标配】
│   ├─ dashboard      数据看板（今日预约/成交额/转化/热门点位）
│   ├─ performance    业绩统计（按摄影师/城市/渠道）
│   └─ trace          全链路溯源（订单→商家码→推广员）
├─ B. 订单中心 orders/           【订单中心：OMS 全生命周期，客服为中枢】
│   ├─ order-list     订单列表（状态筛选/详情抽屉，实时显示客人新单）
│   ├─ receive        受理（客服接手客人已下的单，录入沟通与收款）
│   ├─ dispatch       客服手动派单给摄影师（自营履约，非派单平台）
│   ├─ task           履约任务（拍摄/修图/交付节点）
│   └─ after-sale     售后工单（改期/补拍/重拍，售后人员处理）
├─ C. 财务中心 finance/          【财务中心：对账/结算/分账】
│   ├─ audit          财务审核（定金尾款到账核对）
│   ├─ reconciliation 对账（订单×企微收款×分成）
│   └─ report         财务报表（营收/渠道/城市维度）
├─ D. 渠道与人员 channel/        【渠道与团队：商家合作+分销+人员角色】
│   ├─ shop           商家合作管理（线下合作商家+专属溯源码物料）
│   ├─ distributor    分销/推广员管理（商家铺码→分成模式核心）
│   └─ staff          人员与角色（客服/财务/售后/摄影师，含档期权限）
├─ E. 内容与商品 content/        【小程序数据配置中心：商品管理 + 素材管理(DAM)】
│   ├─ spot           打卡点/旅拍点位（POI，小程序探索页数据源）
│   ├─ city           城市（开放城市，5 处 RPC 缺口之一）
│   ├─ series         拍摄风格/系列（商品的风格分类维度，非独立商品）
│   ├─ album          照片单品管理（商品①）
│   ├─ photo/samples  样片素材库 = 数字资产(DAM)：样片/成片底片/视频源
│   ├─ package        旅拍套餐（商品②，组合打包）
│   ├─ videoSingle    短视频单品（商品③）⚠️路由键与菜单键不一致见第六节
│   ├─ peripheral     影像周边（商品④）
│   ├─ addon-service  增值服务（修图/加片/改期，内部加购项）
│   ├─ tag            标签管理（风格/场景/热门标签）
│   ├─ content-audit  内容审核（上架前审样片/套餐）
│   └─ shelf-products 商品上下架（货架总控）
├─ F. 运营配置 operationConfig/  【小程序装修+内容】
│   ├─ mini-decor     小程序首页装修（轮播/活动/快捷入口/板块开关）
│   ├─ guide          旅拍攻略（旅拍灵感内容板块）
│   └─ story          品牌故事
└─ G. 系统 system/             【专业后台标配】
```

## 三、逐模块详细设计

下面每个模块给：**目标 / 功能清单 / 核心字段（数据模型）/ 关键交互 / 与小程序·企微联动 / 现有工程对照**。

### A. 运营中心（看板/业绩/溯源）
- **目标**：让老板一眼掌握经营健康度，能追每一笔单的来源。
- **功能**：
  - 数据看板：今日新增咨询、待受理、拍摄中、待交付、本月营收、热门打卡点 Top5、转化漏斗。
  - 业绩统计：按城市/摄影师/渠道(推广员)维度看单量、营收、均价、复购。
  - 全链路溯源：输入订单号 → 展示"客人从哪个商家码进 → 哪个推广员 → 分成比例"。
- **核心字段**：指标卡片配置、统计维度、时间范围、溯源链（orderId↔shopId↔distributorId↔rate）。
- **联动**：数据来自 orders/finance 聚合；溯源链依赖 D 模块的分销绑定关系。
- **对照**：`operation/dashboard`、`operation/performance`、`operation/trace` 三页已存在，需补真实数据聚合逻辑（当前多为 mock）。

### B. 订单中心（OMS）
- **目标**：客人在小程序下单后，后台实时生成可追踪订单，客服接手走到交付闭环（客服是订单中枢）。
- **功能清单**：
  - 订单列表：状态筛选（待受理/已受理/拍摄中/修图中/待交付/已完成/售后中/已取消）、客户、城市、摄影师、金额、来源(商家码/推广员)、操作。
  - 受理/接单（重点：**订单不是客服建的**）：订单的唯一生成入口是**客人在小程序提交预约的那一刻**——提交即自动落库，状态=待受理，客人填的商品/档期/备注/联系方式已全部带过来。客服在订单列表看到「新单」后点「接单」只是**进入处理**，可补录/修正档期与沟通要点，绝不手工重造一张单。少数不走小程序的场景（电话/到店直咨）提供「代客下单」，生成的仍是同一套订单结构（仅 `sourceType=phone/offline` 不同），不是另一套建单逻辑。
  - 摄影师调度：给订单指派专属摄影师+档期（**鹿小鸣自营调度，不是派单给外部**），冲突校验。
  - 履约任务：拍摄→修图→交付 节点推进，每个节点可传图/备注。
  - 售后：改期、补拍、重修、退款协调，挂接原订单。
- **核心字段（order）**：
  ```
  orderId, customerName, phone, city, sourceType(scan/distributor/direct),
  shopId, distributorId, items[{productType, productId, name, price, qty}],
  bookingMode('consult'), status, photographerId, scheduleAt,
  amountTotal, paidDeposit, paidFinal, createdAt, updatedAt, remark
  ```
- **专业订单生命周期（状态机，单一真相源）**：客人提交即 `待受理(pending)` → 客服接单 `已联系(contacted)` → 录定金 `定金已收(deposit_paid)` → 派单 `已派单(assigned)` → `拍摄中(shooting)` → `修图中(editing)` → `待交付(final_pending)` → `已完成(completed)`；异常分支 `售后中(after_sale)` / `已取消(canceled)`。**客服的「接单/联系/录收款/派单」全是在这套状态机上推进订单，不是新建订单**；每次流转记操作人+时间戳（审计留痕）。订单的来源、商品、金额一开始就随客人提交带齐，客服只补充履约信息。
- **联动**：客人在小程序预约下单（微信授权）→ 订单实时进后台（已生成，无需客服建单）→ 客服在订单中心看到并「联系客人」(企微/电话) → 订单内录沟通与收款 → 手动派单给摄影师；企微用于沟通与收定金尾款；交付物(DAM)回挂订单。
- **对照**：`orders/order-list`、`receive`、`dispatch`、`task`、`after-sale` 五页已存在。
- **重要**：`lock_pending` 历史状态保留只读；新单不再有锁单费（已删）。

### C. 财务中心（对账/结算）
- **目标**：因为钱走企微（非小程序收款），财务需手工/半自动核对"订单应收 vs 企微实收 vs 分成应付"。
- **功能清单**：
  - 财务审核：逐单核对定金/尾款到账（客服在企微收，后台标记"已收"）。
  - 对账：订单 × 收款记录 × 分销分成 三方勾稽，差异标红。
  - 报表：营收（按城市/渠道/商品）、摄影师结算单、推广员佣金单。
  - 增值服务计费：订单处理时加购修图/加片/改期（`addonServices`），计入对账。
- **核心字段**：reconciliation{orderId, depositReceived, finalReceived, distributorCommission, photographerSettlement, diffFlag}。
- **联动**：依赖 B 订单金额 + D 分销/人员分成规则 + 企微收款台账（需客服录入或导入）。
- **对照**：`finance/audit`、`reconciliation`、`report` 三页已存在，需接真实对账逻辑。
- **注意**：锁单费 ¥10 已删，对账模型不再含"锁单费"科目。

### D. 渠道与人员
- **商家合作管理 shop**（线下合作商家）：
  - 功能：合作商家 CRUD、合作状态（合作中/已终止）、专属溯源码生成与物料管理、按商家看带来单量/分成。
  - 字段：shop{name, contact, city, status, cooperateAt, codes[], settlementRate}。
- **分销/推广员管理 distributor**（商家铺码→分成模式核心）：
  - 功能：推广员档案、与商家绑定/解绑（**解绑分销≠终止商家合作，两关系独立**）、分成比例、业绩与佣金。
  - 字段：distributor{name, phone, bindShopId, rate, status, earned}。
- **人员与角色 staff**（鹿小鸣团队）：
  - 角色覆盖：**客服**（订单接单/联系/派单中枢）、**财务**（对账结算）、**售后**（客诉退改重拍处理）、**摄影师**（含修图师，履约拍摄与精修）；另含系统角色超管/运营。
  - 功能：人员档案、擅长风格、档期/排班、接单量与评分、角色权限（菜单可见范围由 `roleProfile.menus` 控制）。
  - 字段：staff{name, role(cs/finance/aftersale/photographer/admin/operator), city, styles[], schedule[], load, wecomId}。
- **联动**：B.dispatch 派摄影师取 staff(photographer)；C 分成取 shop/distributor 比例；A.trace 溯源取绑定关系；客服在 B 订单内「联系客人」取 staff.wecomId/phone。
- **对照**：`channel/shop`、`distributor`、`staff` 三页已存在。

### E. 内容与商品（小程序数据配置中心）
这是旅拍后台的"生产车间"——小程序里客人看到的所有商品、样片、打卡点、风格，都从这里配置与上下架，是小程序数据的唯一后台来源（按专业后台做法设计，不取决主观偏好）。

**E1 商品管理（Product CMS）** —— 创建客人能预约的产品：
- **照片单品 album**（商品①）：单组照片产品，归某个风格系列，字段 cover/photoCount/seriesId/price/isHot。
- **旅拍套餐 package**（商品②）：**多个基础商品组合打包 + 组合价**（照片单品/短视频单品/周边任意组合），全站唯一"套餐"概念（删除了独立"短视频套餐"）。字段 items[基础商品引用]+comboPrice。
- **短视频单品 videoSingle**（商品③）：短视产品，type=video+isVideoSingle。⚠️菜单键写的是 `videoProducts`、路由键是 `videoSingle`，需统一（见第六节）。
- **影像周边 peripheral**（商品④）：实物（相册/相框/明信片），字段 stock/price。
- **约拍定制**：特殊预约（单人1h¥200、每+1人+¥100），定价走"5 处 RPC 缺口"之一，目前硬编码 `bookingInfo.js`，需后台可配。
- **增值服务 addonService**：修图/加片/改期，后台内部加购项，不进小程序货架，显示于订单/对账。
- **上架总控 shelf-products**：商品上下架、板块开关排序（照片留影/视频摄像/旅拍套餐/影像周边）。

**E2 素材管理（DAM）** —— 数字资产（样片/成片/视频源）管理：
- **样片素材库 photo/samples**：摄影师作品、样片图、成片底片，按拍摄/订单/摄影师/风格归档，支持批量上传、打标签、设为"前台展示样片"。
- **打卡点 spot（POI）**：旅拍核心资产——城市里可拍的机位/路线，字段 name/city/cover/gps/routeDesc/hot。客人小程序"探索"页数据来源。
- **拍摄风格/系列 series**：**拍摄风格的区分维度，是挂在商品上的分类属性，不是独立商品**。例：一个"照片单品"客人是穿古装拍的，它的拍摄风格/系列就归属"古装系列"。后台维护风格列表（古装/复古/清新/胶片…），创建照片单品/短视频时选所属风格；小程序据此在"风格系列"分区与筛选展示（客人界面不出现"套系"二字）。字段：series{name, cover, desc, order}。
- **标签 tag**：风格/场景/热门标签，统一打在商品与样片上。

**E3 内容审核 content-audit**：样片/套餐上架前审核，防违规图外流。
- **联动**：E 所有内容经 `homeConfig`/`getHomeData` 等 RPC 流向小程序；当前 city/搜索热词/约拍定价/预约须知/隐私 5 处未联调（见六）。
- **对照**：`content/*` 共 12 页已存在（spot/city/series/album/photo/package/videoSingle/peripheral/addon-service/tag/content-audit/shelf-products）。

### F. 运营配置
- **小程序装修 mini-decor**：首页轮播/活动公告/快捷入口/板块开关排序/探索页 banner——对应 `homeConfig`(id=homeStats)。⚠️属 5 处 RPC 缺口之一（小程序读 homeConfig，需确认联调）。
- **旅拍攻略 guide**：旅拍灵感内容板块（客人界面"旅拍灵感"），图文。
- **品牌故事 story**：品牌调性内容。
- **对照**：`operationConfig/mini-decor`、`guide`、`story` 三页已存在。

### G. 系统（专业标配）
- **操作日志 log**：谁在何时改了哪条数据（审计留痕，财务/客诉纠纷必备）。
- **回收站 trash**：软删除恢复，防误删商品/订单。
- **对照**：`system/log`、`trash` 已存在。

## 四、核心业务流（端到端闭环，按你的纠正重捋）

```
① 客人在小程序预约下单（需微信授权登录）
      │  订单已在后台生成（状态：待受理），无需客服代建
      ▼
② 后台订单系统实时显示新订单 → 客服在订单列表看到"有新单"
      │
      ▼
③ 客服点订单上的「联系客人」→ 直接拉起企业微信（因微信授权可知客户身份）
      │  未加好友时退回用客人预留手机号 tel: 联系
      ▼
④ 沟通在订单内留痕（沟通时间线/备注）+ 收款金额记录在订单（定金/尾款，走企微收，后台标记已收）
      │
      ▼
⑤ 客服手动「派单给摄影」→ 选专属摄影师+档期（自营调度，非派单平台）
      │
      ▼
⑥ 摄影师履约：拍摄 → 修图 → 成片（DAM 素材回挂订单）
      │
      ▼
⑦ 交付（企微发成片）/ 异常走 B.after-sale 售后工单（改期/补拍/重拍，售后人员处理）
      │
      ▼
⑧ C.财务：审核到账 → 对账(订单×企微收款×分成) → 报表(摄影师结算/推广员佣金)
      │
      ▼
⑨ A.溯源：任一订单可追 商家码→推广员→分成
```

**关于「联系客人」能不能做到**：能。客人在小程序预约必须微信授权登录，后台订单存有客户微信身份（openid/unionid），企微侧边栏或订单上「联系客人」按钮可直接对该客户发起会话；同时保留「打电话」用预留手机号。前提：客户需是企微外部联系人（首次联系时由客服加好友），未加好友时退回电话。我会把「联系客人」做成订单详情的固定操作，企微/电话双通道。

**客服是订单中枢**：接单、联系、记录沟通与收款、派单，都在订单中心（B）内完成——所以订单中心是后台最重的模块，UI 上订单详情要集成"联系/记录/派单"一气呵成的操作区。

## 五、后台 UI 设计规范（UI Designer 专业部分）

作为 UI 设计师，我给后台定一套**贴合鹿小鸣品牌、又符合专业后台效率诉求**的视觉与交互规范。

### 5.1 布局框架
- **左侧分组导航**：七大区折叠菜单（运营/订单/财务/渠道人员/内容商品/配置/系统），当前菜单高亮，二级"内容资产/商品货架"可折叠（现有 `app-shell.js` 已支持）。

### 5.2 设计令牌（鹿小鸣暖胶片国风，给 Element Plus 做品牌主题）
```

鹿金点缀  #FFD36A（选中/徽标高亮，仅小面积）
成功 #10B981 / 警告 #F59E0B / 错误 #EF4444 / 信息 #3B82F6（语义色）

```
- 把 Element Plus 默认蓝主题覆盖为上述令牌：`:root{ --el-color-primary:#EE2C2C; --el-bg-color-page:#FFF7EF; ... }`，保证全站一致。

### 5.3 组件与交互标准
- **状态徽标**：订单状态用色块徽标（待受理=橙、拍摄中=金、已完成=绿、售后=红、取消=灰），一眼可读。
- **图片类**：DAM/样片/打卡点封面统一"卡片缩略图 + 点开大图 + 批量上传 + 拖拽排序"。
- **金额类**：财务/对账表格右对齐、千分位、差异标红。
- **表单**：必填校验、手机号格式、价格非负数；长表单分步（商品组合、套餐选品）。
- **空状态**：无数据给引导（"去新建第一个照片单品"+ 鹿图标），不用空白。
- **权限**：按 `roleProfile.menus` 隐藏无权限菜单；敏感操作（删商品/改分成）二次确认 + 写日志。

### 5.4 无障碍与效率
- 表格行高 ≥ 44px（触控/点击舒适）；文字对比达 AA；键盘可操作筛选与表格；列表支持列固定与导出 Excel（财务/对账刚需）。
- 后台不做暗色（与小程序一致，统一浅色暖胶片）；如未来要，令牌已预留切换成本极低。
