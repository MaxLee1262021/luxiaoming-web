# 摄影师账号同步创建

新增摄影师统一使用“摄影师分成管理 → 新增摄影师”。“摄影师账号”区域参照新增商家，由管理员填写必填的登录账号和登录密码。PH 编号仍由系统生成，登录账号使用管理员输入值，角色为摄影师，并绑定本人的 PH 档案。档案、初始比例、建档日志及系统认证账号在同一事务中提交，账号冲突或任一写入失败均整体回滚。

合作协议编号在保存时自动生成，格式为 `PH-XY-YYYY-NNNN`（年份及四位年度流水号，例如 `PH-XY-2026-0001`），跳过已有协议编号。新增页面只显示“保存后自动生成”，不再要求手填；保存后的实际编号在摄影师列表与详情中查看，历史协议编号保持原值。

“结算方式”使用下拉选择：日结、周结、月结，默认月结。所选方式与档案一起保存，并在列表及详情中显示；保存失败保留选择，取消或重新进入新增页恢复默认月结。旧档案未填写结算方式时按月结展示。此次修改为档案配置，不改变已有的按完成月份归集对账和线下登记发放流程。

登录账号去除首尾空白、最多 128 个字符，不允许控制字符或平台保留的 admin 账号；登录密码须为 8–128 位，包含字母和数字，按原样处理。数据库只保存密码哈希，建档响应、档案、日志、查询和导出均不包含密码。该账号会出现在“权限管理 → 人员”中，摄影师使用管理员填写的账号密码登录后只可查看和导出本人分成，后续密码重设仍通过权限管理进行。

保存成功后返回摄影师列表并清除表单密码，不再弹出自动生成密码。校验或保存失败保留表单，便于修改重试；重置、取消、离开页面及切换登录账号会清除输入的密码。登录信息由管理员按既有安全渠道交付摄影师。

旧“人员账号管理”与“权限管理 → 新增人员”原先能选择摄影师角色，但仅生成普通人员身份，缺少 PH 档案绑定，无法通过摄影师登录校验。现在这些新增入口引导到专用建档页；直接调用旧新增 API 也会返回 `409 / PHOTO_PROFILE_REQUIRED` 和目标路由 `photoNew`，不会写入半成品人员或账号。已有人员和账号的正常编辑、启停及密码重设保留，不自动迁移或重绑历史账号。

本次不新增数据库结构，也不创建真实测试摄影师。测试使用隔离 SQL/账号数据验证原子创建、失败回滚、旧入口拦截、系统账号列表、本人登录和权限范围。
