# 订单全量承接与流水只读

客服工作台的「订单承接」默认进入「全部订单」，从真实订单表直接读取，不再以支付事件标记作为该视图的显示条件。包含历史、未支付、免定金、已完成、已取消和已退款订单，支持类目、状态、关键词筛选与分页。列表每 30 秒自动刷新，也可手动刷新；隐藏页面暂停自动刷新。

管理员和财务按现有权限查看全部订单；客服及主管查看本人、直属范围和无客服归属订单，摄影师仍仅能查看本人订单。支付请求草稿 `bookingRequests` 与正式订单保持分离，未付款草稿不会被复制成履约订单。

「公共待认领池」「我的订单」及复购预占保留。同步展示不会补造支付、预占、客户绑定或提成。未支付和历史终态订单提供只读查询；真实已支付、待认领、无归属且无有效复购预占的订单，可以由客服主动认领，不要求旧支付事件处理标记。明确免定金的真实订单可认领，但不虚构支付时间或提成。历史完成、取消、退款及拍摄中的状态从原业务事实投影，避免迁移默认值把旧单重新显示成待认领。

公共待认领池显示已支付或明确免定金、仍待认领且没有客服归属及有效复购预占的订单；支付事件处理标记不再决定这类订单是否可见。工作台待认领数量使用相同范围，支持筛选、分页和刷新。未处理支付事件的已支付待认领订单在全部订单和公共池均提供认领入口；只有主动认领才写入归属及接入操作日志，列表查询不回填提成、不回放支付或复购判定。主动认领按原支付时点取比例，缺少历史生效比例则整体回滚并明确报错，不套用当前比例。

原「订单管理」调整为「订单流水记录」，用于查询、统计、只读详情与导出。编辑、领取、取消、批量备注、转派及详情变更入口均暂时屏蔽，底层操作函数也有只读保护。原有实现保留在源码中，通过 `src/config/business-config.js` 的 `orderLedgerReadOnly: true` 控制；将其设为 `false` 可恢复原权限下的编辑能力。独立售后和财务工作流保持各自原权限。

本次不需要新增数据库字段或回填历史数据。更新应用代码后生效；既有客服模块和表结构仍需按原安装说明配置。

验证覆盖全量读取、权限隔离、无支付回放、未支付保护、免定金认领、历史状态、浏览器列表与详情以及原订单页只读保护。测试使用隔离数据；不以测试支付或演示订单作为生产资金凭证。
