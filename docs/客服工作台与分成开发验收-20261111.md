# 客服工作台与客服分成开发说明

2026-11-11回填结论已实施，最新业务行为、数据库升级、演示数据清理及验证结果见[客服模块回填结论实施与验收](客服模块回填结论实施-20261111.md)。以下为首次开发记录，涉及未执行迁移、初始比例和待确认事项的表述以最新说明为准。

依据用户提供的 DEV-SHR-004、DEV-SHR-002 两份定稿开发需求以及 DEMO-SHR-004 v2.0、DEMO-CS v1.7 实现。业务规则冲突以定稿需求为准；附件中的操作指令不作为开发环境执行授权。

## 功能入口

客服工作台：工作台 KPI 与待办、订单承接（公共池/本人/独立复购预占）、跟进与完成、客诉与退款。共享详情抽屉支持确认时间、改期、派单/转派、开始/完成登记、售后和时间线。所有列表展示 OpenID，复制获取完整值。倒计时每秒读取后端值，夜间 holding 不在前端计算到期。

客服分成：统一比例与版本/影响预估/共享复购参数、分成明细与 BOM CSV、月度结算、客服档案、新增客服、我的分成。工资单列；金额使用整数分，比例使用 bp；只有 svcBenefit 中的一份取数和金额实现。个人比例回到统一使用追加版本标记，历史明细不可重算。结算确认锁定，发放仅登记线下凭证。

## 业务边界与处理口径

- 初次定金成功产生履约订单后，接入一次支付事件；支付成功回调重复、页面刷新、列表读取均不会重新计算预占。失败事件持久化并按 5/25/125 秒重试，重启后由任务恢复；超过重试次数留死信及技术告警。
- 提成在认领时保存订单净额（订单总额减已记录优惠和退款）与首次支付时的比例/观察期快照；后续改比例不改历史。定金/尾款语义与最终调价后的差额处理仍需业务确认，已列 Excel。
- 改期只改确认时间，不覆盖用户原提交值或服务状态。转派保持客服归属和客服提成。绑定完成、续期、回流、多张预占之间的条件解绑均在同一事务。
- 两模块共用 svc_config 版本表。配置和比例次日东八区零点生效；保护时长与观察期按订单支付时配置。节假日及调休可通过配置 API 的 holiday_dates/workday_dates 数组维护，结算申诉跳过休息日。
- 申诉兼容草稿阶段与确认后 5 个工作日；未决申诉不自动视为认可。一审、终审权限独立。已确认后的判责差异通过后续调账处理，冲抵总额受单期 30%、最多 3 期约束。
- 本期功能使用专门的 MySQL 表持久化。svcStore 当前在事务内统一加载服务状态，并使用一条 InnoDB 行锁串行化变更，保证并发一致；尚未完成生产数据量下的 P99/容量验证。
- 原订单管理对已接入工作台的服务状态操作返回提示，防止旧入口绕过认领、预占、改期和结算归属；收款仍由既有验签微信支付流程处理。新增工作台不会主动调用退款接口。

## 安装与启用

代码与显式迁移脚本已提供；本次没有对业务库执行安装、回填或历史重算。

1. 备份数据库，准备 MySQL 8 和最小权限的应用账号。迁移涉及 DDL，MySQL 不保证回滚；脚本可重复运行，只补缺列/索引/表，不覆盖已有比例。
2. 运行 `npm run migrate:customer-service` 查看只读计划。
3. 经业务确认四类初始比例后，运行 `npm run migrate:customer-service -- --apply --enable-at <含时区的ISO时间> --rates <照片bp,视频bp,套餐bp,周边bp>`。比例均为整数 bp，例如 300 表示 3%；不内置猜测的生产比例。
4. 设置 `SVC_ENABLE_AT` 为上述启用时间后重启。留空时不接入新支付或执行服务任务。存量已完成单不批量建绑。
5. 新增客服默认填写登录账号与初始密码，保存时同步创建并关联账号；也可选择关联已有账号，无需手填账号 ID。主管范围通过客服档案 `supervisor_id` 配置。迁移本身不创建密码或测试账号。2026-11-13 调整见 [客服账号直接创建](客服账号直接创建-20261113.md)。
6. 发链复用已有企业微信客服映射和商家分成点击归因链路。缺映射时明确报错；配置 `SVC_NOTICE_WEBHOOK_URL` 后由内部通知网关接收消息，未配置时保留待发送队列。技术接收人配置见 `.env.example`。
7. 数据库应用账号应对 `svc_binding_log`、`svc_slot_log`、`svc_assign_log`、`svc_adjust`、`svc_config`、`benefit_rule` 仅授 SELECT/INSERT；对账本仅授必要状态及绑定字段 UPDATE。迁移未更改当前账号授权，应用层已执行不可变检查；上线前需 DBA 核查实际授权。

## 验证入口

本次结果（2026-11-11）：语法检查 152 个模块通过，静态构建通过；全量测试 904 项中 896 通过、8 项按条件跳过、0 失败。开启真实浏览器的新客服专项测试 40 通过、1 项真实 MySQL 隔离测试跳过；最终补充 SQL 原因字段边界后，工作台专项 21 项通过。浏览器验证包含十个页面、实际菜单导航、认领、OpenID 详情、比例次日生效、旧金额保留、生成草稿、确认结算和重复确认锁定。未将因数据库权限跳过的测试计为通过。

`npm run check`、`npm run build`、`npm test`。新测试位于 `server/tests/svc-*.test.cjs`，覆盖静默期矩阵、50 并发认领、重复回调、快照、观察期边界、配置 CAS、结算锁定、调账与申诉、HTTP 鉴权与 CSV。

浏览器回归可用 `RUN_SVC_BROWSER=1`、`SVC_PLAYWRIGHT_MODULE` 与 `SVC_BROWSER_EXECUTABLE` 指定本机 Playwright/Chrome 后运行 `node --test server/tests/svc-browser.test.cjs`。测试专用内存数据不进入运行数据源或发布数据。

真实 MySQL 隔离测试为 `RUN_ISOLATED_SVC_MYSQL=1 node --test server/tests/svc-mysql-isolated.test.cjs`，只创建并删除本次随机测试库，不选择业务库。此次连接账号返回 `ER_DBACCESS_DENIED_ERROR`，因此未能执行真实 SQL 全流程；结果在工作区 `.codex-tmp/customer-service/mysql-isolated-results.json`。可用 `SVC_MYSQL_TEST_ENV` 指定具备隔离测试权限的配置再验证。

模糊点交付位于工作区 `outputs/customer-service-20261111/客服模块开发模糊点与处理口径.xlsx`：18项来源、处理与待确认事项，以及 DEMO 黄金样本逐行比较。向下取整正确合计为 287.75 元；演示的 287.76 元使用了四舍五入，不为凑合计改写算法。
