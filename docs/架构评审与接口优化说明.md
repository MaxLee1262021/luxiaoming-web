# 架构评审与接口优化说明

## 本轮结论

当前服务是 Node.js 单体进程：`server/index.cjs` 负责 HTTP 分流，`server/lib/api.cjs` 承担管理端 API、鉴权、订单、文件和审计，`server/lib/rpc.cjs` 承担小程序 RPC。业务数据和权限数据分别使用 MySQL 连接池。

本轮保留旧的 `/api/collection/*` 和 `/api/rpc/*` 兼容契约，同时将后台菜单数据读取迁移为受服务端边界约束的模块接口，避免一次菜单激活产生大量浏览器请求。

## 已实施

### 请求与关键节点日志

- 每个 API 请求生成或继承 `X-Request-Id`，并输出 JSON Lines 访问日志。
- 完成日志包含 `requestId`、`module`、`route`、`method`、`status`、管理员操作者标识/角色、`durationMs`、`dbQueryCount`、`dbDurationMs`。
- 增加登录成功/失败、会话异常、权限拒绝、服务启动/停机、支付回调、业务审计成功/失败和 MySQL 慢查询/事务日志。
- 日志清洗会排除 password、token、secret、Authorization、openid、手机号、微信标识及完整请求体；慢查询仅记录 SQL 操作类型和表名，不记录参数。

常用事件：

```text
http.request.completed
auth.login.succeeded
auth.login.failed
auth.access.denied
api.module.loaded
business.audit.recorded
database.query.slow
database.transaction.slow
payment.notification.accepted
```

### 按模块读取

后台菜单改用：

```text
GET /api/modules/{module}?keys=orders,shops,...
```

服务端在 `server/lib/apiModules.cjs` 固定模块可读集合，并在读取前执行既有角色、菜单和数据范围校验。客户端只能请求当前模块允许的子集，不能通过参数读取其他集合。当前包含 `dashboard`、`operations`、`orders`、`finance`、`channel`、`content`、`configuration` 和 `system` 模块。

旧集合接口仍可用；在滚动发布中，浏览器遇到旧服务的 404 会自动回退到逐集合读取。

### MySQL 列表性能

`mysqlSource.list()` 已将关系数据读取从“每条主记录逐个查询属性和关系表”改为批量 `IN` 查询并按父 ID 水合。订单等关系较多的集合不再随记录数线性增加 SQL 次数。

`DB_RELATION_BATCH_SIZE` 默认 500，用于限制单条 SQL 参数数量和内存占用。业务池与权限池使用同一个可配置的 `DB_CONNECTION_LIMIT` 上限，但两者是独立连接池，部署时应按数据库连接预算核算总量。

### 审计边界

浏览器已停止 fire-and-forget 写入 `/api/collection/logs`。该入口现在拒绝客户端 POST；订单、售后、财务和普通资料变更继续由服务端业务动作写入权威审计记录，避免操作失败仍留下“成功”日志以及重复写库。

## 生产排障

在 systemd 环境中可按请求 ID 串联日志：

```sh
sudo journalctl -u luxiaoming-admin -f
sudo journalctl -u luxiaoming-admin --since "10 minutes ago" | grep 'requestId'
```

建议先关注 `http.request.completed` 中的 `durationMs`、`dbQueryCount` 和 `dbDurationMs`，再用同一 `requestId` 查找鉴权、业务审计、慢查询或支付事件。不要把日志写回业务 `logs` 表，避免数据库故障时进一步放大请求压力。

## 后续优先级

1. 为订单、售后、内容目录提供分页、字段投影和按数据范围下推的 SQL repository；当前兼容集合接口仍会读取完整集合。
2. 将建单全局进程锁替换为数据库唯一约束、幂等查询和事务化容量预留。删除锁之前必须验证正式迁移已创建订单号和预约幂等唯一索引。
3. 为权限菜单和角色策略增加 revision 缓存与批量属性水合，撤权时通过 revision 即时失效。
4. 对公开脱敏目录单独增加短 TTL 缓存和显式失效；订单、支付、权限、文件接口继续保持不缓存。
