# 客服个人时效编辑

“新增客服 → 第三步 · 分成时效”中的链接有效期和结算等待期已改为可编辑，保存时与客服账号、档案和初始分成规则一起写入。

- 链接有效期：整数 1–30 天。后续给该客服订单生成链接时按此值计算，主管代发也使用订单归属客服的配置。
- 结算等待期：整数 0–30 天，0 表示订单完成后无需等待即可结算。每条新提成明细保存个人等待期快照，后续配置变化不会重算既有明细。
- 新建时默认使用当前生效的共用配置，可直接修改；重置恢复当前已加载的共用配置。迟到的加载响应不会覆盖手工输入。
- 配置按客服个人保存；旧档案两列为空，继续沿用原有共用规则。其他客服、既有链接到期时间和历史提成快照均不改写。

数据库迁移：`022_svc_staff_timing.sql` 为 `svc_staff` 增加两个可空整数列，已纳入 `migrate:customer-service`。已有环境只补执行该文件即可，无需重跑初始化或重算历史。迁移前完整备份位于工作区 `.mysql-backups/customer-service-timing-before-20261113.sql`。

验证：`server/tests/svc-staff-timing.test.cjs` 和 `src/tests/svc-staff-timing-ui.test.cjs` 覆盖保存、范围、零等待、回退、异步默认值、发链、快照和回滚。全量测试通过 1060 项、跳过 15 项，语法检查与构建通过。当前 MySQL 已完成加列及真实事务保存后回读验证，测试档案、规则和日志在同一事务中回滚，既有档案保持不变。
