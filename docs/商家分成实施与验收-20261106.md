## 已确认实施口径

| 编号 | 开发口径 |
| --- | --- |
| N01/N02 | 新模块资料为权威来源，旧商家入口移除；新详情维护基本及资质资料。 |
| N03 | 恢复营业不恢复失效绑定，必须重新扫码；注销后重新合作创建新商家。 |
| N04/N05 | 无旧码兼容；扫码次数和趋势只统计当前有效码，绑定人数为与该店存在有效历史扫码绑定的人数。 |
| N06 | 分成入账时间为尾款到账加“平台退款窗口期（天）”，默认3天、允许0–365天；窗口前不生成分成。基数为整单实际到账减成功退款。进入待拍摄（已安排摄影师）后不能申请定金退款。 |
| N07/N08 | 仅线上支付及退款，无人工收退款；加价、改价、优惠纳入商品成交金额，无平台券。 |
| N09/N10 | 冲抵归实际生成明细月份；商品名完整拼接并保存纯文本，不随商品删除消失。 |
| N11 | 默认本月，导出当前筛选全量；2000条仅为业务量预估，不是导出截断或硬上限。不提供全部历史的一键导出。 |
| N12/N13 | Web商家后台，一号一店，新商家立即开户；旧商家页移除，经营统计使用新分成归属。 |
| N14/N15 | 上线切换清理旧账号和角色，仅保留超管；旧商家分佣及未结金额清零。提供显式迁移命令，不在服务启动或页面访问时执行清理。 |
| N16 | 实际启用日待定，由配置设置；存量商家重新录入，旧比例和绑定不迁移。 |
| N17/N18 | 企微发送流程及运行依赖仍待定；实现采集、异步任务和告警对接能力，实际通道与联调需部署配置。 |
| N19 | 严格准入，由市场人员确认合作意向后建档。 |
| N20/N21 | 财务科目/开票待定，本期不开发结算；隐私及合同文案由超管负责。 |

尾款支付时点是固定的业务判定时点，比例按该时点版本、客服时效按扫码时点版本匹配。未入账任务只做预判，入账前仍按原时点重放完备事实，避免较早付款的延迟事件遗漏；支付后的新扫码及新配置不会改变此前判定。退款窗口控制入账时间，不把归属业务时点改到窗口结束。成熟前成功退款减少净基数，成熟后成功退款新增幂等冲抵，不改正式快照。

## 部署与切换

本次开发没有执行真实库迁移、账号清理或旧账清零。以下命令是可审查的部署步骤，不在服务启动、页面访问或单元测试中自动执行。

1. 先验证数据库备份可恢复，使用维护账号运行只读预检：`npm run migrate:merchant-share -- --reset-legacy`。
2. 仅安装新域表、不可变快照触发器及菜单：`npm run migrate:merchant-share -- --apply`。
3. 按用户确认N14/N15执行一次性切换清理：`npm run migrate:merchant-share -- --apply --reset-legacy --confirm RESET_MERCHANT_SHARE --backup-confirmed`。清理保留全部超管账号、属性及授权（停用状态不恢复），且必须存在唯一有效内置admin作为安全锚；删除非超管账号/角色，将旧商家比例、商家转账及商家调整金额清零；保留历史订单及其他角色业务。已有新商家时拒绝首次清理；已完成清理后重跑不再次清理新账号。
4. 重新录入新商家资料及首规则，立即创建一号一店的商家账号。原旧商家入口不再开放，旧绑定和旧码不接入新分成。
5. 在实际业务启用日期定案后设置`SHARE_ENABLE_AT`（带时区的ISO时间，例如`YYYY-MM-DDTHH:mm:ss+08:00`），重启服务。未配置时不采集新分成绑定、不产生分成任务。退款查单恢复独立运行，不因分成未启用而停用。

应用账号对`lxm_share_snapshot`及审计/更正凭证仅授SELECT/INSERT，维护账号负责迁移。`016_share_immutability.sql`同时增加禁止UPDATE/DELETE触发器，避免已有数据库级宽权限绕过审计约束。更正使用独立修订凭证和正负明细，原快照不改。应用角色及菜单授权由现有权限系统管理；“分成授权”仅授查看/配置，管理与资金更正固定由超管执行。新域标识列使用区分大小写的排序规则，避免不同OpenID被数据库合并；门店名称单独保持名称去重规则。

分成操作授权：先在既有权限中心创建账号/角色并配置菜单，再由超管进入“配置列表→分成授权”授予查看或配置权限。配置权限包含查看；受保护业务角色保持只读，用户重新登录后取得更新的授权。商家账号由入驻事务创建，只能读取本人“我的分成”。

超管可在“配置列表→规则说明”底部查看11项全局参数，支持刷新和失败重试，无编辑入口。启用日和告警标志只表示配置有无；启用时间按北京时间展示，告警已配置不代表通知已送达。

## 运行配置及对接接口

- `SHARE_ENABLE_AT`：必需的正式启用时间，当前业务日期待定；不在代码中替运营决定。
- `CS_ATTR_DAYS`：客服点击窗口，默认7天；`MAX_CANDIDATE_MERCHANTS`默认20。
- `SHARE_ALERT_WEBHOOK_URL`：运营/P1通知的HTTPS接收端；`SHARE_PHONE_ALERT_URL`：P0电话告警适配端。请求带事件幂等标识；未配置或失败不会记为已送达，保留重试/失败状态。
- `WECHAT_PAY_REFUND_NOTIFY_URL`：微信退款通知地址，默认基于支付通知域名派生`/api/payments/wechat/refund-notify`；需在部署域名实际可达并通过微信验签回调验证。
- 既有微信小程序配置用于生成真实可扫商家码，不使用演示码图作为生产回退。

运行任务按北京时间执行：每日03:30全量漏单补偿、整点成功退款扫描、每日09:00未配置商家提醒、每日01:15统计前一日指标。另有每秒成熟任务分发及每分钟持久标记恢复、未成熟预判复核；退款查单不依赖新分成开关。调度槽、租约及有限补偿游标落库，支持多实例与重启恢复。判定默认初次失败后再按1/4/16秒重试三次，第四次仍失败进入人工队列。支付回调只持久化付款凭证及投递标记，分成数据读取/计算均在后台任务中；关闭服务先停止接新HTTP，等待投递及后台任务结束后再关闭数据库连接。

管理接口统一在`/api/share`：`rules`、`rules/save`、`merchants`、`merchants/:id`、`merchants/:id/status`、`merchants/:id/qr`、`merchants/:id/qr/rotate`、`details`、`details/export`、`mine`、`analytics`、`settings`、`grants`。商家登录只允许`mine`及必要的会话操作；查询商家ID从会话得出，不接受客户端越权切换。

内部管理入口：`GET /api/share/failures`查询失败队列，`POST /api/share/jobs/:orderId/retry`带原因重试失败任务，`POST /api/share/snapshots/:orderId/correct`由超管提交原因和幂等请求标识进行不可变更正，每月最多10次。更正后的后续退款按最新修订基线冲抵。

`GET /api/share/failures`同时返回失败任务与失败通知，`POST /api/share/alerts/:eventId/retry`可在修复通道后重试通知；`GET /api/share/audit/export`导出最近2000条审计记录。定稿原路径`/admin/share/...`及`/internal/share/snapshot`提供兼容入口，仍执行相同身份验证；内部快照请求从已保存订单和在线凭证读事实，不接受调用方伪造金额、客户或订单来源。

统计分开两个口径：所选期商家净额来自明细实际生成月份，订单当前余额来自全历史账本及最新更正。跨月退款不会把旧订单的累计分成变成负数用于总部扣减。平台、零金额及窗口内订单仍有归属映射；城市按订单业务城市筛选，二维码扫码和绑定人数为门店累计，不能解释为消费城市的扫码/绑定细分。

新商家应计在旧对账页只读，不参与旧商家结算；其他角色核算保留。总部金额仅在当前授权和原有入池订单集合内扣减对应商家当前余额。

订单原`source`保留现有渠道对象；正式结果通过持久outbox回写`shareOrderSource`、`shareServiceStaffId`、`shareCsClickId`、`shareSourceReason`及`shareAttributionRevision`。同步读取最新有效更正并使用CAS，旧事件不能回退新修订；失败不确认事件。订单辅助字段不作为新分成的判定输入。较早支付或退款事实晚到且影响已入账结果时，只产生人工复核风险，不自动改已入账资金。

账户注销对接为`POST /api/share/users/invalidate`（仅超管，必填`userId/reason/requestId`）或内部`store.invalidateUser()`。它使资金归属绑定失效并保留历史凭证，不代替账户系统删除个人资料/撤销会话；账户系统应在正式注销及再次开放该身份交易前完成该同步。普通退出登录不调用它，新真实扫码可建立新的绑定。

跨城市及争议监测只消费可信内部采集源：`recordObservation({metricKey:'SCAN_CITY',subjectId:qrId,valueText:cityCode,...})`、`ATTRIBUTION_DISPUTE`按订单主体采样。扫码城市不从商品消费城市猜测，不新增客户端GPS采集。当前未提供实际城市或争议源时，指标明确返回未采集/null，不显示为0；该数据源按N18运行依赖对接。当前有效码扫码量较前7日均下降90%时提示运营核实，风控不自动改变商家归属或拦截订单。

企微流程待定期间，提供可信链接生成与采集接口：超管通过`/api/share/staff-map`维护映射，已授权客服通过`POST /api/share/cs-links`生成登记过的随机链接（必带幂等标识）。小程序`reportShareClick`只接受有效登记链接的客服身份；自行拼接staff/link参数只记缺失，不判客服来源，也不建立绑定。具体发送卡片/侧边栏接入由企微流程定案后配置。

小程序授权摘要已同步定稿中的“扫码后您的消费将与提供服务的门店关联，用于门店结算”告知。完整政策正文仍由后台配置提供，最终文案及发布由超管负责（N21）；本次没有修改已发布政策配置。
