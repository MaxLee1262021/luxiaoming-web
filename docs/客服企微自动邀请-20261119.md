# 新增客服自动邀请企业微信

在客服列表保存新客服后，系统先提交本地档案、登录账号及比例规则，再调用企业微信通讯录接口创建或复用成员，将其加入“客服”部门，并提交单人邀请。已有成员保留原有部门。无论选择新建登录账号还是关联已有账号，均执行同步。

“客服”指企微组织架构中的部门（截图 ID 为 2），不涉及“微信客服”接待人员接口。邀请提交后仍需本人确认加入，企微可能因频率限制不重复发送通知，页面不会将接口成功表述为本人已激活。

## 部署配置

已有客服模块的服务器在部署新代码、启动服务之前，备份数据库并执行增量迁移：

```bash
npm run migrate:wecom-contacts
npm run migrate:wecom-contacts -- --apply
```

第一条只显示计划，不连接数据库。第二条为 `svc_staff` 增加企微绑定及同步状态字段，并在缺失时创建共享企微映射表 `lxm_share_staff_map`，已有映射保留。迁移可重复执行，不修改分成比例、客服权限或支付接入时间，也不邀请历史客服。新安装客服模块时，完整的 `migrate:customer-service` 也包含此迁移。只执行通用 `migrate:mysql` 不会补齐这些字段。

在服务器 `.env` 中配置：

```dotenv
WECOM_CONTACT_SYNC_ENABLED=true
WECOM_CORP_ID=企业ID
WECOM_CONTACT_SECRET=通讯录同步Secret
WECOM_CUSTOMER_SERVICE_DEPARTMENT_ID=2
WECOM_CONTACT_TIMEOUT_MS=10000
```

通讯录同步须有成员创建和编辑权限，服务器出口 IP 须在企微可信 IP 配置中，且可访问 `https://qyapi.weixin.qq.com`。企业 ID 与现有客服小程序使用的企微主体保持一致。这里的 Secret 是通讯录凭据，与小程序 AppSecret、微信支付密钥、机器人 Webhook 不同。凭据只放服务器环境，不能配置到网页或版本库。保存环境后重启后台服务。

## 操作及异常恢复

- 正常新增：填写姓名、手机号及后台账号等必填项，保存一次。列表展示同步结果，成功后自动保存后台登录账号与企微成员的分享映射。
- 同步失败或未启用：本地档案和账号仍保留，提示明确说明企微尚未完成；超管可在该行点“重试企微同步”，无需重复建档。
- 网络中断或进程退出：同步状态保留。正在同步的任务在五分钟后允许重新接管；再次创建成员时使用稳定 ID，并处理已有手机号，不重复创建成员。同步完成后的重复请求直接返回已保存结果。
- 映射冲突：不会覆盖其他客服的映射。核对商家分成模块中的企微映射，修正后再重试。
- 历史档案不会被后台批量邀请；需要时由超管逐条发起同步。已终止档案禁止同步。

本地新增接口为 `POST /api/svc/staff`，重试接口为 `POST /api/svc/staff/:id/wecom-sync`，重试仅允许超管。响应及列表包含 `wecom_userid`、`wecom_department_id`、`wecom_sync_status`、`wecom_sync_message` 和同步时间，不返回企微访问令牌或 Secret。

## 接口依据与验证范围

对接企业微信官方[创建成员](https://developer.work.weixin.qq.com/document/path/90195)、[邀请成员](https://developer.work.weixin.qq.com/document/path/90975)和[获取成员 ID 列表](https://developer.work.weixin.qq.com/document/path/96067)接口。创建时关闭默认邀请，然后通过单人邀请接口提交，检查无效接收人。已有成员的部门通过 ID 列表聚合后合并，兼容新通讯录凭据无法读取成员详情的限制。

自动化验证使用模拟 HTTP 响应和隔离存储覆盖正常创建、已有成员、邀请失败、凭据及网络异常、重试、权限和映射冲突。未使用真实企业通讯录进行成员创建或邀请；部署配置齐全后需在实际企业中验收一次。
