## 一、整体架构（一句话看懂）

- **技术栈**：Vue 3 + Element Plus，**免构建（no-build）**——`index.html` 用一排 `<script>` 加载运行库（`public/vendor/`），页面按需 `loadScript` 动态加载 `src/views/{folder}/{slug}.{js,html,css}`。
- **路由**：`src/router/index.js` 里 `LXM_PAGES` manifest 共 **30 个页面**（含 login / dashboard / 订单 / 财务 / 渠道 / 内容 / 运营 / 系统）。
- **核心设计（关键）**：每个页面 `.js` 只是「注册壳」——绝大多数 `setup(ctx){ return {} }`，**所有共享状态、计算属性、方法都集中在 `src/app.js`（约 300KB 巨型 god-object）里**；它通过 `Vue.provide('lxm', ctx)` 注入，页面组件的 `setup` 返回 `{...ctx}`，于是 `.html` 模板里能直接用到 `state`、`financeReviewOrderRows`、`openFinanceReview`、`money`、`can(...)` 等。
  - 例外（自带逻辑的页面）：`content/city`、`content/videoSingle`、`operationConfig/mini-decor`、`system/log`、`system/trash` 这 5 个 `setup` 返回了真实对象。
- **数据层**：当前 no-build 前端跑的是 **app.js 内存态（mock，`LXM_DATA` 来自 `src/mock/`）**；`server/index.cjs`（端口 5192）是一套**独立、可运行**的后端（json / mysql / mock / cloud 四种模式），提供 `/api/collection/{name}` 与 `/api/rpc/{name}`。**前端尚未默认指向它**，所以「真联通」= 给视图加一个服务层去调 `/api`。
- **品牌皮肤已就绪**：`src/styles/tokens.css` 是「唯一令牌源」，已定义全套 `--lxm-*`（暖胶片：品牌红 `#EE2C2C` / 活力橙 `#FF8D52` / 焦糖墨 `#2A211B` / 奶油 `#FFF7EF`），并把旧变量（`--brand/--blue/--nav…`）重定向到品牌色，Element Plus 主色也改成了品牌橙。**所以 B（美化）是「用好现有令牌做打磨」，不是从零搭皮肤。**

## 二、财务审核（重点）—— 已完整实现

### 2.1 业务流（与你描述完全一致 ✅）
```
客服登记定金  → order.depositPaid=N, depositFinanceStatus='待审'        （app.js ~L2458 / L2524）
客服登记尾款  → order.finalPaid =N, finalFinanceStatus  ='待审'        （app.js ~L2503 / L2547）
售后登记退款  → 售后行 refundAmount=N, refundConfirmed=true, financeStatus='待审'（app.js ~L1961-2018，时间线写「退款售后已提交财务审核」）
        ↓
财务审核确定   → reviewRefundFinance(row, approved) → financeStatus='已审'/'已驳'（app.js ~L2128-2152）
                写入 financeReviewedBy / financeReviewedAt，记操作日志 + 订单时间线 + log()
```
- 同一订单在审核台合并成一行，列出「预约定金 / 收尾款 / 退款审核」多项审核事项（`financeReviewOrderRows`，app.js ~L2053）。
- 顶部统计：`待审核 / 已审核 / 已驳回 / 当前金额`（`financeReviewSummary`，app.js ~L2083）。
- 权限闸门：`can('financeReview')` —— 仅 `super` + `finance` 角色可审（business-config.js roles）。
- 导出：`openExportDialog('financeReview')` 支持导出审核明细报表（app.js ~L5500 / L5736）。

### 2.3 一个命名坑（技术债，建议顺手修）
- `src/api/auditService.js` 名叫「审核服务」，但里面只有 **摄影师资质审核**（listPhotographerApplications / approvePhotographer），**不是财务审核**。财务审核逻辑全部散在 `app.js`，没有独立 finance service。命名易误导，建议改名或补充 financeService。
- `src/api/orderService.js` 边界正确：**后台不做收款/支付/提现/结算**，只查询订单、改状态、读微信核销/成交结果（`getPaymentVerificationStatus`）。这与「资金线下/小程序侧完成」的铁律一致，保持不变。
