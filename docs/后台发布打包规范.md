# 后台发布打包规范

本规范是麓小鸣后台 Linux 发布包的唯一执行约定。默认从当前工作区的 `luxiaoming-admin-交付包` 生成源码部署包，目标运行目录是 `/opt/luxiaoming-admin`。服务器上的 `.env`、数据库、Redis、OSS、微信支付私钥和证书不进入默认发布包。

## 一句话触发约定

用户说“打包后台项目”“重新打包后台项目”“按规范打包后台”或“生成 Linux 后台发布包”时，直接按本规范执行完整流程，不再询问包名。只有用户指定了其他目录、版本号或是否携带 `.env` 时才覆盖默认值。

每次发布使用当天中国标准时间和一个从未使用过的名称，推荐格式：

```text
luxiaoming-admin-linux-YYYYMMDD-updater-rN
```

已有同名目录、`.tar`、`.tar.gz` 或 `.tar.gz.sha256` 时递增 `rN`，绝不覆盖已有产物。

## 打包前检查

在正式源码根目录执行：

```bash
npm run check
npm run build
npm test
```

`check` 检查 JavaScript 语法，`build` 检查静态入口结构，`test` 必须没有失败项；仓库已有的明确跳过项可以保留。Git Bash 可用时还检查部署脚本：

```bash
bash -n deploy/linux/install.sh
bash -n deploy/linux/start.sh
bash -n deploy/linux/update.sh
```

任何检查失败都不能生成可交付包。打包不清理、重置或提交用户的 Git 改动。

## 标准打包命令

使用项目自带脚本，不能手工复制目录替代：

```bash
npm run package:linux -- --name luxiaoming-admin-linux-YYYYMMDD-updater-rN
```

Windows PowerShell 示例：

```powershell
cd "D:\idea\travel-photo\luxiaoming-admin-交付包"
npm run check
npm run build
npm test
npm run package:linux -- --name luxiaoming-admin-linux-YYYYMMDD-updater-rN
```

默认不使用 `--include-env`。只有用户明确要求携带本机配置时才使用该参数；此时 `.env` 必须按 `0600` 处理，并在交付结果中明确标注敏感包。

## 包内白名单和排除项

固定根文件：

```text
.env.example
index.html
package.json
package-lock.json
README.md
docs/OSS接入与迁移.md
docs/oss-ram-policy.json
docs/微信支付接入说明.md
docs/最新订单流程与迁移.md
```

固定目录：`public/`、`src/`、`server/`、`scripts/`、`deploy/`。

默认排除 `.env`、其他环境文件、`node_modules/`、`.git/`、`.codex-tmp/`、所有测试目录、`server/data/`、数据库备份、上传物、缓存、编辑器文件和任何本机密钥。该包是源码部署包，不生成 `dist` 或独立可执行文件，也不把 Windows 的 `node_modules` 带到 Linux。

归档前将 `deploy/linux/**/*.sh` 统一转换为 LF，并设置 POSIX `0755`。当前包必须包含：

```text
deploy/linux/install.sh
deploy/linux/start.sh
deploy/linux/update.sh
scripts/prepare-linux-update.cjs
```

`update.sh` 和 helper 必须一起发布，不能只复制 `update.sh`。

## 产物和校验

输出位于源码目录的上一级：

```text
RELEASE_NAME/
RELEASE_NAME.tar.gz
RELEASE_NAME.tar.gz.sha256
```

脚本自动生成兼容 `sha256sum -c` 的校验文件。交付前执行：

```bash
sha256sum -c RELEASE_NAME.tar.gz.sha256
```

并确认归档只有一个顶层目录，可以在 Linux 用 `tar -xzf` 解压，不含 `.env`、`node_modules`、`.git`、测试目录或 `server/data`，部署脚本是 LF/0755，systemd 仍使用 `/opt/luxiaoming-admin` 和 `deploy/linux/start.sh`。

## 交付结果

每次“打包后台项目”都必须返回：

1. `.tar.gz` 下载链接。
2. `.tar.gz.sha256` 下载链接。
3. 实际包名、文件大小和 SHA256。
4. `check`、`build`、`test` 的结果。
5. 是否包含 `.env` 的明确说明。
6. 上传和校验命令。

上传格式：

```bash
scp RELEASE_NAME.tar.gz RELEASE_NAME.tar.gz.sha256 用户名@服务器IP:/tmp/
cd /tmp
sha256sum -c RELEASE_NAME.tar.gz.sha256
```

不在回复、日志或校验输出中打印 `.env`、数据库密码、OSS 密钥、微信支付私钥或证书内容。

## 服务器更新约定

服务器已安装更新器后，普通更新使用：

```bash
sudo bash /opt/luxiaoming-admin/deploy/linux/update.sh /tmp/RELEASE_NAME.tar.gz
```

更新器会保留服务器 `.env`、应用目录内的 `certs/` 和 `.env` 引用的项目内支付文件，先安装依赖和检查语法，再停止服务、备份 MySQL、切换代码并检查 `/api/health`。

只有发布说明明确包含 MySQL 结构变更时才追加：

```bash
sudo bash /opt/luxiaoming-admin/deploy/linux/update.sh /tmp/RELEASE_NAME.tar.gz --migrate
```

`--migrate` 只执行 `npm run migrate:mysql -- --apply`。订单数据迁移、文件迁移和其他业务迁移按各自文档单独执行，普通打包不自动触发。结构迁移一旦开始，后续失败会保留现场并停止服务，不自动回退数据库。

首次从没有更新器的旧版本升级时，先将新包完整解压到临时目录，再运行临时目录里的 `deploy/linux/update.sh`；必须同时保留 `scripts/prepare-linux-update.cjs`。

## 安全边界

- 不读取、打印或提交服务器真实 `.env` 内容。
- 不默认使用 `--include-env`。
- 不把支付密钥、证书或数据库备份放进发布包。
- 不覆盖已有发布产物或服务器当前目录。
- 不在打包阶段连接生产数据库、执行生产迁移、发起支付或修改 OSS。
- 代码目录可以回退；数据库结构和业务数据必须使用已验证备份及迁移文档处理。

服务器细节见 [Linux 部署说明](../deploy/linux/README.md) 和 [中文部署、后台常驻与打包运行说明](../deploy/linux/部署运行说明.md)。
