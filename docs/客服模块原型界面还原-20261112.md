# 客服模块原型界面还原

此轮原型外观重构已按用户后续更正撤回。当前以[客服模块字段对齐与样式回退](客服模块字段对齐与样式回退-20261112.md)为准：保持原后台风格，仅按DEMO补齐业务字段和名称。以下保留为历史记录。

按用户提供的《客服工作台-交互演示-DEMO-SHR-004-v2.0.html》和《客服分成模块-交互演示-DEMO-CS-v1.7.html》重构工作台四页、分成管理六页。

## 页面和组件

- 外壳采用原型白色顶部栏和侧栏，替换客服模块原有深色导航。顶部栏52px，工作台侧栏238px、分成管理侧栏240px；内容最大宽度分别1180px、1220px，正文边距22px/26px，标题20px。工作台蓝色 `#3b5bdb`，分成管理绿色 `#0f6e56`。侧栏显示KF/CS页面编号，并使用当前账号的真实菜单授权。
- 工作台还原独立KPI卡、今日待办、订单承接双页签、我的订单内的紫色预占区、客户绑定卡、跟进/完成双页签、企微发链以及行内客诉登记、改判和调账记录。
- 订单详情使用580px右侧抽屉，头部保留改期、提交售后、转派、关闭；正文使用步骤、信息字段和跟进时间线/分成计算/操作三个页签。改期和转派在抽屉内展开对应蓝色、橙色面板。
- 分成管理还原当前版本与只读比例、四类比例表、影响预估、共享复购参数、版本历史与单独比例列表；明细页采用四KPI、独立筛选卡、十二列表格及批量选择条。
- 人员列表使用十列结构，600px详情抽屉内包含四类比例、变更原因、保存/改回统一、版本及历史记录；新增客服使用三个分步卡片。我的分成使用本人信息、四KPI、结算进度和个人明细。
- 统一卡片边框、圆角、间距、表头和行高、输入框、金额等宽排版、OpenID复制、状态标签和按钮颜色。移动端保留导航开关，长表格横向滚动。

## 保留的业务结论

需求定稿和用户已确认的结论继续生效：提成按已收定金、比例5/10/8/15%、快照不可重算、整数分向下取整、主管仅代直属组且保留原归属、纯实物收货后完成、手工标签/复核日、共享放假/补班日历、结算确认锁定及确认后5工作日申诉。

原型中的身份切换、模拟支付、演示数据、伪造通知成功和调试按钮没有进入正式业务页面。列表和统计来自真实接口；新增统计字段覆盖筛选后的全部记录，不能用当前分页的几行冒充总量。财务人员的姓名筛选由明细接口提供授权范围内的人员选项，无需额外获得人员管理权限。

本次没有执行SQL、数据清理、数据库迁移或远程发布。修改在本地源码中；部署时更新前端资源和新增展示汇总接口代码即可。

## 验证

- 浏览器逐页检查十个页面的顶部栏、导航、内容宽度、标题坐标和主色，并测量580px/600px抽屉；验证先进入明细页时懒加载样式仍正确。
- 检查实际菜单导航、退出客服模块后的主题隔离、移动导航、十二列表格、抽屉内改期、真实业务提交和资料维护。
- 倒计时每秒使用后端返回的 `left_seconds`，夜间冻结；慢请求不重叠，页面隐藏暂停请求，过期响应不能覆盖较新列表。
- 新增并验证统计分页/人员范围、导航授权、原型组件及人员抽屉行为测试；执行全量测试、语法检查及静态构建。

最终结果：全量1036项测试中1023通过、13按条件跳过、0失败；语法检查162个模块通过，静态构建通过。真实浏览器的业务回归、原型几何、收货与人工资料、倒计时与请求并发检查均通过。手机顶部栏的品牌、导航按钮和账号胶囊另按390px视口逐项断言处于52px顶栏内。原型几何断言允许抽屉变换计算产生的不足0.1px浮点误差，不放宽布局尺寸。
