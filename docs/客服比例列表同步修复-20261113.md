# 客服比例列表同步修复

客服个人比例保存时会追加次日零点生效的新版本。原人员列表只读取当前生效版本，因此保存成功、关闭编辑窗口或刷新列表后仍显示旧比例。

现在人员列表及客服档案显示最新已保存的配置。尚未生效时展示“待生效”和具体生效时间，档案同时保留当前生效比例，便于核对。保存完成后重新查询列表并同步打开的档案；关闭后重新打开或刷新页面也读取相同结果。

后端 `GET /api/svc/staff` 保留 `rates` 的当前生效语义，增加 `configured_rates`、`rate_pending` 和 `rate_effective_at` 作为人员管理展示数据。跟随统一比例时解析真实统一版本，不使用切回统一标记中保存的旧比例快照；同一生效时间以最新版本为准。

订单核算继续按支付时点生效版本执行，已产生的提成快照保持原值。本次不涉及数据迁移或修改用户保存的比例。

验证覆盖个人比例保存后立即回读、重复保存、跨日生效、切回统一比例、统一比例待生效版本、首次建档、人员范围，以及前端弹窗和抽屉保存后的列表同步。真实 MySQL 中已确认现有客服有待生效版本；另在回滚事务中验证保存和回读，测试变更全部回滚，账本和原生效比例保持不变。

专项测试：`server/tests/svc-staff-rate-projection.test.cjs`（7 项）和 `src/tests/svc-staff-rate-refresh.test.cjs`（5 项），全部通过。前端测试使用真实分成服务与测试存储，覆盖保存请求、后续查询、列表和详情变化，不只模拟静态返回值。
