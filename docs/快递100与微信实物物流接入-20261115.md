# 快递100与微信实物物流接入

本次增加服务端适配及隔离测试。没有注册、充值、调用真实发货接口或将凭据写入仓库。交易域及 HTTP 接线与其他实物购买改动共同部署，不能单独将这份说明当作销售开通记录。

## 配置与正常流程

使用 [配置字段模板](physical-commerce.env.example) 在服务端私有环境设置快递100查询/订阅账号、回调地址，以及适用账号的微信发货管理配置。模板没有真实凭据。

客服一次确认发货会保存包裹、版本和非空随机 `subscriptionSalt`，快递100订阅引用已保存的同一盐。用户物流页先读本地，交易服务统一限制同运单远端查询频率。适配器本身不以进程内缓存代替跨进程限频或持久任务。

建议回调路由：`POST /api/physical/logistics/kuaidi100/notify?subscriptionId=<包裹ID>:<版本>`，接收表单字段 `param`、`sign`。先按标识读取持久化包裹版本，再调用 `parseNotification(body, storedShipment)`；必须用该版本的已存盐验签，不能接受请求携带的盐。合法旧版本归档而不覆盖新运单；未知标识、伪造签名或不匹配单号不能修改订单。

`createKuaidi100()` 提供 `subscribe(shipment)`、`query(shipment)` 和 `parseNotification(body, shipment)`。结果包含物流维度、去重轨迹、快照摘要和包裹版本，不执行订单完成、退款或库存变化。重复订阅错误仅说明平台已有订阅，不证明回调地址、盐或当前版本一致；系统不能直接把它当作本版本订阅正常。

订阅所需字段：`id`、`version`、`carrierCode`、`trackingNo`、`subscriptionSalt`，以及对应快递公司要求的 `phone`。回调地址需按当前快递100账号验证 HTTPS 支持，不能降为无保护的公开查询接口。

## 微信发货与收货验证

`createWechatShipping()` 提供 `upload(shipment, order)` 和 `queryReceipt(order, shipment)`。快递100小写公司编码与微信公司编码分别维护；未映射时明确阻止微信同步，不直接传用另一平台字典。

本地出库确认不是承运商揽收。适配器只在已保存人工交接核实记录、`collectedAt` 或可信揽收/运输状态时执行微信上传，未满足时返回 `WECHAT_SHIPPING_AWAITING_HANDOVER` 供后台任务后续重试。首次外部调用前保存当前版本固定的 `wechatUploadRequestAt`，同一版本重试保留相同上传排序时间，避免丢响应后新建重发；该字段不是实际交接时间。上传返回的 `uploadedAt` 须持久化到当前包裹的 `wechatUploadedAt`，不可从旧版本继承。

查询使用真实微信交易号，校验返回付款人及支付单归属，并核对当前有效包裹单号、微信公司编码和该版本上传时间。缺少关联证据时不将微信收货结果用于完成新版本。

官方 `get_order` 状态为：1 待发货、2 已发货、3 确认收货、4 交易完成、5 已退款、6 资金待结算。适配器仅将状态 3 视为本次可验证收货事实；状态 4/6 不冒充收货。平台未提供确认方式或确认时刻时分别返回 `unknown`、`null`，本地观察时间单独记录。若回查时已经错过状态 3，且没有持久化的可信确认记录，应保留平台状态并进入核对，不以“已结算”补造收货。

文档核对来源：[微信发货上传](https://developers.weixin.qq.com/miniprogram/dev/server/API/order_shipping/api_uploadshippinginfo.html)、[微信订单查询](https://developers.weixin.qq.com/miniprogram/dev/server/API/order_shipping/api_getorder.html)、[快递100订阅/通知](https://api.kuaidi100.com/document/5f0ffa8f2977d50a94e1023c.html)。核查日期：2026-11-15。

## 验证和恢复

隔离验证命令：`node --test server/tests/physical-providers.test.cjs server/tests/physical-logistics-integration.test.cjs`。覆盖通知验签、盐/版本与运单匹配、查询签名、重复订阅及额度错误、微信交接前置、收货状态/当前包裹关联、付款人越权、后台任务不重入，以及真实解析器与交易领域连接后的版本稳定、监控中止、撤销后迟到通知和售后冻结。

上线前需有真实账号的订阅成功、可达回调及轨迹更新证据；微信适用账号另核对发货上传、当前包裹查询和可信收货事件。测试没有替代真实联调。

`physicalWorker` 启动后调用交易服务的持久任务处理，单进程不重入，关闭时等待进行中的任务；不自动建表或清空历史。交易服务须在数据库中控制任务租约和去重，多进程部署不能只依赖 worker 的内存标记。平台错误记录脱敏错误码，不记录 URL 中的 access token、密钥、盐或用户完整资料。
