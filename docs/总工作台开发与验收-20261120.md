# 总工作台 V1.3 开发与验收

本次在 `svcGeneralWorkbench` 新路由实现总工作台。前稿四项调整仅在新页面生效：确认时间到派单的两步向导、已有派单记录到转派入口、档期冲突二次确认、企微直接联系。原工作台概览、订单承接、跟进与完成等入口继续执行原流程。业务订单共用，新页面成功操作后原页面正常看到最新状态。

## 实现范围

- 六张统计卡、完整分页、筛选联动、服务订单九态、预占倒计时与全部六类行按钮。
- 向导分别调用原确认与派单接口；第一步成功、第二步取消或失败时保留确认结果。未知结果先核对状态，避免重复写入。
- 已派单记录查看不写入，明确进入转派后才调用原转派动作；档期冲突允许确认继续，不在服务端增加档期强制拦截。
- 新入口的列表、详情、备注、工具弹窗和复用售后详情/复制内容进行展示脱敏，旧入口默认展示不变，业务对象不被脱敏文本覆盖。
- 新工作台内接入原客户绑定、企微发链、商品外链、改期审核、客诉判责、实物发货及原获权配置。
- 改期与未结售后卡使用完整真实队列。主管没有原真实售后办理权时，不通过新卡扩大权限；原客诉改判仍独立保留。

## 入口与数据接口

新页面位于 `src/views/service/general-workbench/`，独立保存组件状态、向导步骤、请求序号与定时器。共享客服工具仅在显式传入 `ctx.kfIsolation` 时使用新实例上下文，旧调用默认不变。

新增接口：

- `GET /api/kf/workbench/general`
- `GET /api/kf/workbench/general/queues?queue=reschedule|complaints`
- `POST /api/kf/workbench/general/reschedule-review`
- `GET /api/kf/photographers/{photo_id}/occupancy?from=YYYY-MM-DD&days=14`
- `POST /api/kf/orders/{order_no}/contact`

新路径独立检查总工作台菜单，继续使用原订单范围与原角色能力。只拥有旧菜单不能调用新增接口；具有新菜单的合法客服不需要通过放宽旧 `orders` 菜单权限才能在新入口审核改期。旧改期审核路径的菜单门禁保持原样。

## 已有 MySQL 环境的菜单安装

代码中已登记新菜单及默认客服角色。已有的权限数据库需要单独增加菜单；不要为本次新增菜单重跑整套旧业务迁移。

```powershell

node scripts/install-general-workbench-menu.cjs

# 在目标部署环境正式安装
node scripts/install-general-workbench-menu.cjs --apply
```

安装器只新增 `svcGeneralWorkbench` 并授予现有启用的 super/service/service_supervisor 角色。若该菜单已存在，则不覆盖其停用状态、排序或既有授权，不恢复被人工撤销的权限。普通客服首次创建角色时也包含总工作台；已有角色原授权不因开户被重置。

本次开发未执行 `--apply`，未连接生产数据库，也未部署或重启线上服务。

## 企业微信直接联系

已实现官方 JS-SDK `openEnterpriseChat` 的会话准备、签名、当前客服与外部联系客户关系校验及客户端调用。该能力需要企业微信客户端、自建应用、可信域名与真实客户外部联系人映射。普通浏览器和缺配置场景会明确报错，不以生成服务链接代替直接联系，也不声称消息已经送达。

## 关闭与回滚

通过原权限管理停用新菜单/撤回新授权即可关闭入口；旧菜单与旧流程继续使用。企微直接联系另由 `WECOM_GENERAL_CONTACT_ENABLED` 控制。回退代码前先关闭新入口，保留旧调用契约。已经成功写入的认领、确认、派单或转派记录不回滚；停留在已确认未派单的订单可从旧入口按原流程续办。
