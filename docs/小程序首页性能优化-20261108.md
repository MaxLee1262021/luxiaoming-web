# 小程序首页与查询性能优化

日期：2026-11-08。代码已在本地完成，尚未发布至线上。

## 已处理的等待与重复读取

| 位置 | 调整前 | 调整后 |
| --- | --- | --- |
| 普通冷启动 | 默认启动页固定等待 3 秒后跳转首页 | 默认页面直接进入首页，保留原启动页地址 |
| 商品读取 | 首页响应后逐本请求相册详情，全部完成才显示首页 | 按最终展示范围移除首页商品卡片及详情补查，目录保留用于搜索建议 |
| 首页点位目录 | 额外为首页聚合完整点位商品 | 首页传 `includeSpotProducts:false` 省略聚合，商品在探索详情和旅拍灵感展示 |
| 首页集合查询 | 同一请求重复读取城市、系列、打卡点 | 请求内共享进行中的读取；后续请求重新获取最新发布状态 |
| MySQL 关联读取 | 每批各关系表依次等待 | 连接池并发读取独立关系表；事务专属连接保持原有串行顺序 |
| 首页展示 | 首张轮播图延迟加载，隐藏页面仍更新热词 | 首图立即加载，隐藏后清理定时器；相册关联查找改用 Map |

## 可复核的数据

相同的隔离测试场景（一个公开城市、一个点位、空商品列表、显式空轮播）中，首页底层数据源 `list/get` 调用由 16 次降至 8 次：

- `cities`：4 → 1。
- `series`：4 → 1。
- `spots`：3 → 1。
- 相册、套餐、周边、灵感及首页配置各读取一次。

这里统计的是数据源调用次数；一次 MySQL 集合读取可能包含主表和多张关系表 SQL，不能将该数字理解为总 SQL 条数或线上耗时。

20 本相册的测试中，相册集合仍只读取一次，首页不逐本查询相册记录。新版前后端配合时不再发出相册详情补查；搜索配置仍独立请求。

## 兼容性与验证

每次返回首页仍同步最新后台内容。请求缓存仅存在于一次只读 RPC 内，不跨请求保留，不用于预约和订单写入。热榜分页与刷新保留版本校验，过期响应不能覆盖新结果。

回归覆盖城市与扫码来源、商品显隐、全局相册、显式清空图片、显式解绑、超过 100 个点位的分页、相册详情一致性，以及 MySQL 批次记录隔离和事务回滚。

- 后台全套：763 项通过，4 项按既有环境条件跳过，0 失败；最终相册兼容调整后再次通过 40 项相关测试。
- 小程序全套：121 项通过，0 失败；111 个 JS 文件语法检查通过。
- 后台 `npm run check`：119 个模块通过；`npm run build` 项目结构检查通过。

## 发布与实际测速

完整效果需要更新后台服务和小程序。可先更新后台，再发布小程序；新版小程序也兼容旧后台，首页均不再补查相册详情。最终展示范围及后续验证见《首页与探索商品展示范围》（`打卡点热榜商品展示-20261108.md`）。

本次无需数据库迁移、新增索引或新增依赖。实际线上耗时尚未测量；发布后应以同一网络、同一城市和同一数据集，在微信真机测冷启动、返回首页、切换城市与热榜追加，并比较服务端请求耗时及慢查询记录。
