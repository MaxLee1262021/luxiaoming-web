# 客服模块回填结论实施与验收

以用户回填的《客服模块待确认事项-白话说明版》8项回复及此前确认的业务结论为本次实现依据。本说明更新了此前开发说明中的待确认项。

## 最终行为

| 事项 | 已实现行为 |
| --- | --- |
| 草稿内提成展示 | 保留用户指定的“已结算”文字。结算单仍区分草稿、已确认、已发放，账务状态和确认锁定规则不变。 |
| 客诉改判补回 | 按最终改判结果处理，不增加额外财务审核。尚未确认的账单恢复提成，已确认的账单保持原数，通过后续结算补发；退款扣回与客诉判责不重复扣减。 |
| 旧订单、旧账 | 按用户确认的演示数据范围清理，不导入新客服账本。清理前保存可恢复SQL备份及支付凭据。 |
| 纯实物完成 | 客服或直属主管明确确认“客户已收货”后即可完成，无需摄影师或虚构拍摄步骤。观察期从收货登记时点开始；重复提交不重复记账。 |
| 人员标签、复核日期 | 超管或直属主管可手工维护自由文本标签与下次复核日期，允许清空，不自动评分。记录改前、改后、原因与实际操作人。 |
| 工作日历 | 超管维护放假、补班日期。工作台及比例设置页面读取同一份配置，拒绝无效日期及放假/补班冲突。未配置年份仍按周一至周五处理，不能视为已取得公司年度日历。 |
| 统一初始比例 | 照片5%、视频10%、套餐8%、周边15%。已安装为客服统一v1；以后调整追加版本，不覆盖历史快照。 |
| 企微对接 | 由超管提供企微对接与故障接收人配置。界面写明负责人，配置缺失不会伪造“通知已发送”。 |
| 已收定金计提 | 客服提成基数使用已收定金。例如实收定金200元，周边15%，提成30元。新明细落金额及比例快照，尾款到账和总价变化不会重新计算这条旧明细。摄影师报酬继续使用自己的原有金额口径。 |
| 主管代办 | 只覆盖本人和直属客服，不递归覆盖间接下属。可代直属客服认领、接预占、放弃、发链、改期、派单、完成、客诉处理及申诉；订单、提成和客户保护仍归实际客服，记录真实操作人。统一参数、财务确认发放等仍按各自角色权限执行。 |

## 已完成的数据库操作

升级了客服工作台、分成账本、手工标签、复核日期、收货与代办留痕结构。现有订单表接近MySQL单行定义上限，迁移将两个无索引的展示文字字段 `sourceName`、`seriesName` 从可空VARCHAR扩展为可空TEXT，保留原值和查询含义，再补充新增客服字段。迁移脚本可重复执行，已有比例不会被覆盖。

正式初始客服比例已落库，生效时点为北京时间 **2026-11-11 16:12:21**。

演示数据清理截止北京时间 **2026-11-11 16:00:00**，实际清除：21个旧订单、23个旧预约、5条售后、1条调账及关联数据，共19表6991行。旧线上测试支付凭据也保存于清理前的备份中。未删除OSS实物文件。

清理后复核：订单、预约、售后、调账、订单/预约支付记录为0；11个登录账号、15个套餐、4个周边商品、原商家配置及5条商家审计记录保留。未创建新的业务客服档案或测试订单。

清理计划及结果在工作区 `.codex-tmp/customer-service-confirmed/`，可恢复备份在工作区外层 `.mysql-backups/customer-service-confirmed/`。备份不放入源码或发布包，已复核SHA256一致。

## 验证结果

- 全量测试963项：954通过、9项按条件跳过、0失败。
- 实际浏览器回归3项通过，覆盖十个页面、认领、详情、比例保存、结算锁定、收货完成、人员标签/复核日期和工作日历控件。
- 真实MySQL单连接事务测试通过：手工资料可重读、直属主管代办保留归属、200元已收定金按15%计提30元、无摄影师收货完成幂等、改判恢复及结算确认。所有合成测试记录均已回滚，并按表计数复核无残留。
- 单独建隔离数据库的测试仍需要建库权限；本次真实SQL验证改用现有库已安装结构上的单连接外层回滚事务，没有将权限受限的测试算成通过。
- 语法检查和静态构建通过；清理工具默认只读，执行要求准确清单hash，并在首个DELETE前完成备份与校验。

## 上线时的操作

代码及数据库结构已准备完毕，本次没有发布到远程服务器或重启现有服务。上线前由超管完成：关联真实客服登录账号、填写年度放假/补班日历、配置企业微信人员及通知渠道。发布时设置 `SVC_ENABLE_AT` 为实际启用时间，再启动服务；新支付事件才接入客服流程。当前本机启用时间及企微通知通道尚未配置。

如重新安装，可运行 `npm run migrate:customer-service -- --apply --enable-at <含时区的启用时间>`；缺省初始比例采用本次确认的5/10/8/15%，已有规则不覆盖。生产环境执行前仍应备份，清理工具不随服务启动自动运行。
