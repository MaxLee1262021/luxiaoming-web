# 商家码最近扫码归属规则

日期：2026-11-18。本文执行用户本次明确的规则，取代旧文档中客服订单按时效、候选商家及历史自主订单优先筛选归属的说明。

用户原话：

> 商家码的溯源及统计规则：1）客户第一次扫商家码进小程序，算这个商家的；2）客户退出小程序后，没有扫其他商家码之前，在平台所有的订单分成都会归到对应最近扫的商家码。
> 一句话：最近扫码的商家享有订单分成，直到扫下个商家码之前。

## 业务规则

客户第一次有效扫描商家码，即归属该商家。客户退出小程序后，直接重新进入或通过普通入口进入，商家归属持续有效；只有有效扫描下一个商家码，才切换到新商家。平台全部商品与服务订单适用，包括旅拍订单和独立购买的实物订单。

订单在既有支付判定时点取该客户最近的有效扫码商家。自主下单（T1）与客服推荐下单（T2）使用同一商家归属规则，分别使用对应分成比例。客服点击只区分订单类型，不替换商家、不触发旧商家优先、不限制商家归属时长。

无有效商家归属时归平台；商家停业、注销和用户注销沿用既有失效处理，不因新规则恢复无效绑定。商家换码不清除已有归属。扫码去重和请求重试继续防止重复计数；退出后直接进入不应生成新的扫码统计。

扫码上报按捕获顺序投递，旧扫码失败时暂停后续扫码，避免旧记录重试夺回归属。支付前先同步待上报的商家扫码；同步失败时提示用户重试支付，避免按旧归属发起支付。直接重进不新增扫码，换码前已建立的有效归属允许继续购买，停用码不能用于建立新归属。

## 统计与配置

“当前归属人数”按每名客户最新有效归属统计，一个客户同一时点只归一家商家。客户先扫 A 再扫 B，A 的当前归属人数减一，B 加一；历史扫码次数保留。扫码量继续按实际扫码事实统计，当前有效码的计数和趋势沿用现有展示范围。

当前配置页仅维护自主比例、客服比例、退款观察期和变更原因，不再提供商家归属时效或候选商家上限。旧版配置中的时效值保留在历史记录，当前归属不使用该值。

分成比例继续按支付时点匹配。旅拍尾款或独立实物全款成功后，经过既有退款观察期生成分成；退款使用负向冲抵，实物订单运费按既有分成金额规则处理。套餐随附的实物履约子单随父单计算，避免重复计提。

## 验收场景

1. 客户首次扫 A 后下单，商家归属为 A。
2. 退出后重新进入，不扫其他商家码，购买平台其他商品及服务，仍归 A，扫码次数不增加。
3. 超过旧客服时效、经客服推荐下单，仍归 A，按客服比例计算。
4. 扫 B 后支付的新订单归 B；重复上报同次扫码不增加次数，旧请求重试不夺回归属。
5. A、B 当前归属人数随切换更新；既有已入账分成和退款冲抵保留各自原商家。
6. 独立实物订单按全款和有效商家归属计提，退款正确冲抵；套餐附带的实物子单不重复计提。

本次不自动重算历史已生成分成，不批量补正历史来源，不修改线上启用时间或直接操作真实资金流水。历史更正继续使用既有核验和审计流程。
