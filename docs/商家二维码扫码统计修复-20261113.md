# 商家二维码扫码统计修复

经营看板原先只读取旧扫码表 `lxm_scans`，商家分成码上报写入 `lxm_share_scan`，两套读取没有打通。同时，未配置或未到达 `SHARE_ENABLE_AT` 时，上报直接跳过，导致商家码已被扫码而没有统计记录。

## 修复行为

- 有效商家码的真实扫码使用服务端确认的微信身份记录，不再依赖分成启用时间。启用前仅记扫码，不创建分成绑定或绑定历史，也不提前开启分成。
- 经营看板、扫码明细及看板聚合接口只读合并新旧扫码事实，不复制写入另一张表。日期与小时统一使用上海时间，去重人数使用访客哈希。
- 商家二维码页面打开时读取实际扫码量；“刷新统计”同时更新扫码量和每日趋势。“刷新数据”重新读取经营看板数据。查看、下载码图和刷新页面都不会增加扫码。
- 小程序为同一次入口的启动、显示及落地回调去重，上报使用稳定请求标识。网络超时后重试不会重复记数；客户端保留五秒重复入口去重，服务端按请求标识去重，无标识的旧客户端保留五秒兜底。
- 看板保留已记录的历史码扫码事实；商家二维码页统计当前有效码，换码后按新码记录展示，绑定和财务历史保留。

## 更新与核验

后台部署本次源码并重启服务，小程序发布本次入口上报修复。已有商家分成表的环境无需新增数据库迁移，`SHARE_ENABLE_AT` 继续仅控制分成归属证据及分成流程。显式退出登录的扫码按原规则暂存，恢复授权后补报。

使用真实商家码扫码，进入后台刷新经营看板及对应商家二维码统计，检查扫码量、人数和每日趋势；再次查看码图或刷新统计时扫码量应保持不变。服务端重试同一请求不增加记录，超过去重窗口再次扫码会新增。

此前被跳过、没有保存到扫码表的访问缺少可核验记录，无法据此补造历史扫码量。

验证覆盖上报到接口读取、分成未启用、上海跨日、请求重试、换码、权限隔离、前端刷新与异步竞态，测试使用独立合成数据。实际数据库只做只读数量与配置检查，未新增或修改业务记录。
