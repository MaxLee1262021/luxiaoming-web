# 鹿小鸣旅拍后台沟通纪要

## 2026-06-28 18点前后台优化基准

- 优先级以早期确认的鹿小鸣后台商业闭环为准：经营看板、订单客服工作台、商家一店一码、人员权限、内容商品管理、小程序首页装修预览。
- 后续参考抖音来客时，只能借鉴成熟后台的交互和底层逻辑，不能偏离早期确认的鹿小鸣业务结构。
- 数据看板顶部卡片必须能下钻，尤其是扫码量、转化订单、成交额、已收定金、已收尾款、待收尾款。
- 订单页必须是客服日常工作台，不是单纯状态流转页面；客服需要筛选订单、联系客人、收定金/尾款、改价、改期、加购、派摄影师、记录跟进。
- 加购页必须按产品结构走：通用加购、全局主推套餐、所有打卡点、打卡点下套餐/短视频/系列/照片单品。
- 人员权限、商家管理、内容商品管理都要服务实际经营，不能只做静态展示。

## 固定业务边界

- 后台不做收款、提现、退款、佣金结算操作，只做订单履约、状态记录、成交统计、月度核对和应计金额展示。
- 客服通过微信线下联系客人、收定金、收尾款、交付成片；后台负责记录过程和同步订单状态。
- 客服订单详情页只服务订单处理，不展示订单溯源与分账明细；溯源、扫码、商家分账放在看板、商家管理、月度对账里。
- 取消订单进入回收站，客服不能永久删除，超管可查看回收站。
- 所有关键操作需要写入操作日志或订单跟进记录。

## 订单工作台

- 订单列表需要能按日期、状态、分销员、来源商家、客服、摄影师、关键词筛选。
- 订单列表需要展示客户、商品、金额、已收定金、已收尾款、待收尾款、预约具体时间、状态、负责客服、摄影师。
- 订单详情需要显示客人预约备注、手机号、微信号、预约时间、商品快照、商品详情入口和加购入口。
- 客服可手动更新内部状态和客人可见状态，状态变化必须留下跟进记录。
- 订单金额支持客服修改成交价、定金、尾款，并自动计算待收尾款，必须填写改价/优惠/加购原因便于超管复核。
- 加购商品从已有商品里选择，不能手写；结构为通用加购、全局主推套餐、所有打卡点、打卡点下套餐/短视频/系列/照片单品。
- 点击套餐要能看套餐详情，点击照片单品要能看样片，样片支持双击放大。

## 数据看板与商家

- 扫码量指扫码进入浏览但未必下单的人，需区分去重访客、浏览未下单、转化订单。
- 看板所有指标要能下钻到明细，扫码明细要能按商家和二维码位置筛选。
- 商家是一店一码，二维码链接格式为 `pages/index/index?shopId=商家ID`。
- 商家管理需要显示商家名称、分销员、二维码位置、扫码量、订单数、成交额、应计分账、登录账号。
- 月度核对需要支持商家、摄影师、客服、分销员的订单数量和成交金额统计。

## 角色权限

- 统一登录入口，不同角色登录后只显示可见菜单和可操作按钮。
- 超管可切换角色预览后台。
- 客服可处理订单、派单、取消订单进回收站，但不能永久删除。
- 摄影师只看自己的任务，不能看商家来源和完整联系方式。
- 商家只看自己门店数据，客户联系方式要脱敏。
- 人员管理只管理内部人员；商家账号在商家管理中维护。
- 角色有默认权限，但超管可以对人员进行单独权限微调和重置密码。

## 内容与商品

- 内容编辑关联字段必须使用下拉、勾选、网格选择，不手写关联 ID。
- 内容结构为打卡点 → 系列 → 照片单品 → 样片。
- 套餐分为本打卡点套餐和全局主推套餐；全局主推套餐不受打卡点限制。
- 短视频是独立产品类型，不等同于套餐目录里的普通套餐。
- 摄影周边、修图、加片、改期等属于通用加购。
- 首页配置需要能维护轮播素材、信任数据、活动文字，并预览小程序前端效果。

## 设计与开发纪律

- 参考抖音来客的成熟结构，但只借鉴适合鹿小鸣的多角色、筛选、批量操作、日志、租户隔离、详情页交互，不照搬无关模块。
- 每次完成稳定功能后必须 Git commit，方便回滚。
- 代码出现乱码或功能大面积损坏时，优先回滚到最近稳定提交。
- 页面要能在 `http://127.0.0.1:5191/` 直接预览。
