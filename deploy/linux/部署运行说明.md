# Linux 部署、后台常驻与打包运行

[后台发布打包规范](../../docs/后台发布打包规范.md)

本项目的管理页面与 `/api` 接口由 `server/index.cjs` 同一进程提供。正式运行使用 Node.js + systemd，关闭 SSH 后继续运行，进程退出后自动拉起，服务器重启后自动启动。默认端口为 `5192`。应用依赖已有 MySQL；生产会话建议使用 Redis。部署包不包含数据库服务。

## 1. 服务器准备

以下命令适用于使用 systemd 的 Linux（如 Ubuntu / Debian / Rocky Linux），需要 sudo 权限。

先安装系统级 **Node.js 24 LTS 和 npm**（也支持 Node.js 22 LTS），可参考 [Node.js 官方安装入口](https://nodejs.org/en/download)。Node 18 / 20 已结束官方支持。不要只安装在个人 nvm 的 `/root` 或 `/home` 下：systemd 的专用用户无法使用这些目录里的 Node。

```bash
node --version
npm --version
command -v node
command -v npm
```

Node/npm 应在 `/usr/bin`、`/usr/local/bin` 等系统路径下。安装包还需要服务器可以访问 npm registry。

## 2. 本地打包与上传

在正式源码目录执行，输出在源码目录的上一级。使用新的包名避免与旧版本冲突：

```powershell
cd "D:\idea\travel-photo\luxiaoming-admin-交付包"
npm run check
npm run build
npm run package:linux -- --name luxiaoming-admin-linux-20261018-updater-r1
scp ..\luxiaoming-admin-linux-20261018-updater-r1.tar.gz ..\luxiaoming-admin-linux-20261018-updater-r1.tar.gz.sha256 用户名@服务器IP:/tmp/
```

这是源码部署包，无需生成 `dist` 或打包成可执行程序；`npm run build` 只检查静态入口。压缩包包含前端、API、锁定依赖清单及部署文件，不包含 `node_modules`、测试数据和 `.env`。在目标 Linux 上安装依赖，避免带入 Windows 依赖。

以后打包替换为新的日期或版本名，已有发布目录、压缩包、临时 `.tar` 或 `.sha256` 文件均不会被覆盖。打包会生成标准 SHA256 校验文件，并统一部署脚本的 Linux 换行和可执行权限。如明确需要随包携带本机 `.env`，可加 `--include-env`；常规部署在服务器单独维护 `.env`。

## 3. 首次解压与配置

以下为首次部署。若 `/opt/luxiaoming-admin` 已有运行版本，请使用第 7 节的更新方式。

```bash
# 首次创建用户；已有用户时跳过这一行。
sudo useradd --system --user-group --home /opt/luxiaoming-admin --shell /usr/sbin/nologin luxiaoming
sudo mkdir -p /opt/luxiaoming-admin
sudo tar -xzf /tmp/luxiaoming-admin-linux-20261018-updater-r1.tar.gz \
  -C /opt/luxiaoming-admin --strip-components=1
sudo chown -R luxiaoming:luxiaoming /opt/luxiaoming-admin
cd /opt/luxiaoming-admin

# 若有原部署配置，改为将原 .env 复制到当前目录。
sudo -u luxiaoming cp -n .env.example .env
sudo chmod 600 .env
sudoedit .env
```

在 `.env` 填写真实配置。下方只表示运行参数，不能用它覆盖已有 MySQL、Redis、OSS、微信等配置：

```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=5192
DATA_MODE=mysql
SESSION_STORE=redis
ALLOW_DEV_OPENID=false
DB_AUTO_MIGRATE=false
PAYMENT_MODE=wechat
TEST_PAYMENT_ENABLED=false
```

填写 `DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME`；使用 Redis 时填写 `REDIS_URL` 或 `REDIS_HOST/REDIS_PORT/REDIS_PASSWORD` 等。已有业务数据保留在原 MySQL 中，部署包不会搬运它。

文件功能需要 OSS 配置；小程序登录需要微信 AppID/AppSecret；微信支付需要商户号、私钥、APIv3 密钥、验签材料与 HTTPS 回调地址。分别参见 [OSS 配置](../../docs/OSS接入与迁移.md) 和 [微信支付配置](../../docs/微信支付接入说明.md)。这些配置尚未完成时，不能用健康检查通过来判断对应业务已可用。

Node 会从工作目录自动读取 `.env`，不需要执行 `source .env`。修改配置后需要重启服务。

## 4. 安装依赖与数据库准备

```bash
cd /opt/luxiaoming-admin
sudo -u luxiaoming sh deploy/linux/install.sh
```

脚本会执行 `npm ci --omit=dev --include=optional` 和语法检查。保留 optional 依赖以使用 Redis。

首次初始化数据库或升级数据库结构时，先完成可恢复的数据库备份，再查看迁移计划；已有同版本数据库无需每次重启都执行迁移。`migrate:mysql -- --dry-run` 只输出本地输入及结构计划，不连接或检查目标库，不能据此判断真实数据库已验证；发布包没有本地 fixture，计划中的数据计数通常为零。

```bash
sudo -u luxiaoming npm run migrate:mysql -- --dry-run
# 确认迁移要求、目标库配置和可恢复的备份后应用结构变更。
sudo -u luxiaoming npm run migrate:mysql -- --apply
# 若尚未创建 OSS 元数据表。
sudo -u luxiaoming npm run migrate:files -- --schema
```

当前订单流程升级还需参考 [最新订单流程与迁移](../../docs/最新订单流程与迁移.md)，先执行只读预览 `sudo -u luxiaoming npm run migrate:order-flow -- --mysql`。需要应用订单数据迁移时，在维护窗口按该文档操作；普通启动不会自动迁移订单。初始化完成后保持 `DB_AUTO_MIGRATE=false`。

可执行 `sudo -u luxiaoming npm run oss:check` 检查文件配置。需要实际验证上传时，使用 `npm run oss:check -- --write-test`，会创建并清理临时对象。

## 5. 设置后台常驻和开机启动

```bash
cd /opt/luxiaoming-admin
sudo -u luxiaoming node --version
sudo cp deploy/linux/luxiaoming-admin.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now luxiaoming-admin
sudo systemctl status luxiaoming-admin --no-pager
curl -fsS http://127.0.0.1:5192/api/health
```

健康接口应返回 HTTP 200 且 `ok=true`。503 通常表示 MySQL、Redis 会话或权限存储尚未就绪，应结合日志检查连接、账号授权和表结构。修改 `PORT` 后，上述 URL 也要换成实际端口；shell 不会自动读取 `.env` 中的 `PORT`。

服务文件关键设置：

```ini
User=luxiaoming
Group=luxiaoming
WorkingDirectory=/opt/luxiaoming-admin
ExecStart=/opt/luxiaoming-admin/deploy/linux/start.sh
Restart=always
RestartSec=5
Environment=NODE_ENV=production
```

`Restart=always` 在进程退出后约 5 秒重启；显式 `systemctl stop` 仍会正常停止。`enable` 设置开机启动。标准输出和错误输出进入 journal，无需额外加 `nohup` 或 `&`。HTTP 503 并不表示进程退出，因此不会单凭一次健康检查失败重启。

常用命令：

```bash
sudo journalctl -u luxiaoming-admin -f              # 实时日志，Ctrl+C 只退出日志查看
sudo journalctl -u luxiaoming-admin -n 100 --no-pager
sudo systemctl restart luxiaoming-admin           # 更新代码或 .env 后重启
sudo systemctl stop luxiaoming-admin              # 停止
sudo systemctl start luxiaoming-admin             # 启动
sudo systemctl is-enabled luxiaoming-admin        # 检查开机启动
```

如出现 `node: not found`，检查 Node 是否位于系统级路径。若修改部署目录，须同时修改 service 的 `WorkingDirectory` 和 `ExecStart` 并执行 `daemon-reload`。如果端口已被旧的 `npm run server`、PM2 或 Docker 进程占用，先停止旧进程再交给 systemd 管理。

## 6. 对外访问与域名

直连验收时访问 `http://服务器IP:5192`，需要在云安全组与服务器防火墙放行实际端口。正式域名建议由 Nginx 提供 HTTPS 并代理到 `127.0.0.1:5192`；使用反向代理后，可把 `.env` 的 `HOST` 改为 `127.0.0.1` 并重启。

已配置域名证书的 Nginx `server` 块中，可使用下列 location，转发整个应用（包括支付回调、`/api/files/`、`/api/media/` 和地图代理）：

```nginx
location / {
    proxy_pass http://127.0.0.1:5192;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

这只是转发片段，域名和 HTTPS 证书由服务器的 Nginx 配置提供。不要让另一份旧静态目录覆盖管理页面。小程序请求域名及微信支付回调需使用有效 HTTPS，并配置到对应微信后台。

## 7. 后续更新与回退

已部署的 `/opt/luxiaoming-admin` 使用 `deploy/linux/update.sh` 完成重复更新。服务器已有系统级 Node.js 24，无需每次重新安装 Node 或运行 apt。脚本要求现有 systemd 服务和可用的 MySQL 配置，以 root 或 sudo 执行；健康检查通过 Node.js 发起。每次选择维护窗口，并将新压缩包与同名 `.sha256` 文件上传到 `/tmp`。

先校验上传是否完整，文件名替换为本次发布包：

```bash
cd /tmp
sha256sum -c 新版本包.tar.gz.sha256
```

显示 `OK` 后，常规更新只需要执行：

```bash
sudo bash /opt/luxiaoming-admin/deploy/linux/update.sh /tmp/新版本包.tar.gz
```

脚本自动执行以下步骤：

1. 校验压缩包结构，解压到独立新目录，复制服务器已有 `.env`、`certs` 目录及 `.env` 中引用的项目内支付密钥/证书文件，安装依赖并检查语法。
2. 停止服务，生成 MySQL 备份；仅在显式传入 `--migrate` 时执行 MySQL 结构迁移。
3. 保留旧目录、切换新版本并启动服务，使用现有 `.env` 的端口检查 `/api/health`。未执行结构迁移的更新若启动或健康检查失败，尝试恢复旧代码并启动；结构迁移已经开始的更新若失败，保持服务停止，等待核对数据库和手工处理。

服务文件和已有 `node-path.conf` 等 systemd 设置继续使用。脚本会显示旧版本、数据库备份和发布结果的位置，保留这些文件供核对和回退。应用目录外的支付文件继续使用原绝对路径；其他需要保留的项目内文件可追加 `--preserve uploads` 等相对路径参数，多项可重复传入。

**首次从旧包升级：** 如果现有项目没有 `update.sh`，先将经过校验的新包完整解压到临时目录，再执行其中的脚本。必须保留完整包目录，因为脚本还需要同包的 `scripts/prepare-linux-update.cjs`。

```bash
update_source=$(mktemp -d /tmp/lxm-updater.XXXXXX)
tar -xzf /tmp/新版本包.tar.gz --strip-components=1 -C "$update_source"
sudo bash "$update_source/deploy/linux/update.sh" /tmp/新版本包.tar.gz
```

**需要结构迁移的版本：** 将上面的更新命令追加 `--migrate`。例如：

```bash
sudo bash /opt/luxiaoming-admin/deploy/linux/update.sh /tmp/新版本包.tar.gz --migrate
```

`--migrate` 只运行 `migrate:mysql -- --apply`，不会自动迁移旧订单业务数据；订单数据迁移仍按 [最新订单流程与迁移](../../docs/最新订单流程与迁移.md)单独预览和操作。普通代码更新不要添加此参数。新版本需要其他迁移时，依照对应发布说明执行。

**回退边界：** 未执行结构迁移时，自动恢复仅处理代码目录。结构迁移一旦开始，迁移、启动或健康检查失败均不会自动回退代码或数据库，服务保持停止；备份用于单独的数据恢复。数据库变更可能已经部分应用，应先核对迁移输出，不能将换回旧代码等同于恢复数据。人工回退前需确认数据库兼容性，再停止服务、换回脚本保留的旧目录并检查健康接口。

## 8. 可选 Docker Compose 运行

若服务器已有 Docker Engine 与 Compose v2，可选择容器方式。systemd 和 Docker 选择一种管理同一个端口。

```bash
cd /opt/luxiaoming-admin
sudo systemctl enable --now docker
sudo docker compose --env-file .env -f deploy/linux/compose.yaml up -d --build
sudo docker compose --env-file .env -f deploy/linux/compose.yaml logs -f
```

镜像基于 Node.js 24，容器内固定监听 `0.0.0.0:5192`，`.env` 的 `PORT` 控制宿主机映射端口。`restart: unless-stopped` 支持退出后重启及 Docker 服务重启后恢复。修改 `.env` 后再次执行 `up -d` 以重新创建容器。

容器里的 `127.0.0.1` 指容器自身；若数据库在宿主机上，请提供容器可访问的数据库地址。宿主机上的支付私钥/证书路径也必须通过只读 volume 映射到容器后才能使用。Compose 仅启动应用，不创建 MySQL 或 Redis。

参考：[Node.js 支持版本](https://nodejs.org/en/about/previous-releases)、[systemd 服务重启规则](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html#Restart=)、[Docker 构建路径规则](https://docs.docker.com/reference/compose-file/build/)。
