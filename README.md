# 麓小鸣长沙旅拍 Web 管理后台

这是麓小鸣旅拍小程序配套的 Web 管理后台，用于管理小程序页面内容、商品资料、上下架状态、运营推荐位和基础履约数据。

当前项目采用原生静态页面 + Vue 3 全局构建 + Element Plus 全局构建，由集成服务提供页面与真实 MySQL API；直接打开 HTML 不会载入任何业务数据。

## 项目结构

```text
luxiaoming-admin/
├─ index.html                 # 应用入口
├─ package.json               # 本地开发脚本
├─ public/                    # 第三方静态资源
├─ scripts/                   # 本地工具脚本
│  └─ serve.cjs               # 静态服务
├─ src/                       # 业务源码
│  ├─ app.js                  # Vue 应用入口与全局状态调度
│  ├─ api/                    # 业务接口封装
│  ├─ components/             # 公共组件
│  ├─ config/                 # 业务配置、角色权限、状态枚举
│  ├─ layout/                 # 后台整体壳层
│  ├─ router/                 # 页面注册与懒加载
│  ├─ styles/                 # 全局样式
│  ├─ utils/                  # 通用工具
│  └─ views/                  # 页面模块
└─ docs/                      # 项目说明与交接文档
```

## 主要模块

- 经营中心：经营看板、数据概览。
- 内容商品：打卡点、系列、照片单品、样片、套餐、短视频商品、周边、商品上下架。
- 运营装修：小程序装修预览、攻略管理、故事管理。
- 预约配置：在「内容管理 → 预约配置」设置默认定金比例和预约须知及版本，并可独立保存小程序隐私政策标题和正文；照片留影与视频摄像可设置独立比例，留空使用默认值。见[预约定金与须知配置](docs/预约定金与须知配置-20261113.md)。
- 订单履约：订单流水记录（查询、统计、只读详情与导出）、拍摄任务、售后服务。客服工作台的订单承接默认展示全部授权订单；原订单编辑代码保留并暂时屏蔽，见[订单全量承接与流水只读](docs/订单全量承接与流水只读-20261113.md)。
- 客服工作台新增「商品小程序外链」：汇总照片留影、视频摄像、旅拍套餐与周边商品，生成并复制直达详情页的微信链接，支持 1/7/30 天有效期。部署及权限安装见[商品小程序外链](docs/商品小程序外链-20261119.md)。
- 渠道增长：人员、分销；原商家管理入口已收敛至商家分成管理。
- 商家分成管理：配置列表、分成明细、商家端；详情、建档及配置作为页内功能。
- 商家码扫码统计独立于分成启用，经营看板汇总真实新旧扫码记录，二维码页可刷新当前码扫码量与每日趋势。见[商家二维码扫码统计修复](docs/商家二维码扫码统计修复-20261113.md)。
- 客服分成管理：分成配置、分成明细、客服列表、结算管理、客服端。客服端直接进入“我的分成”，超管默认查看全部客服并可筛选单人；客服账号仅查看本人。新增客服在客服列表弹窗中完成，成功后重新请求列表。
- 摄影师分成管理：分成配置、分成明细、摄影师列表、结算管理、摄影端。摄影端直接进入“我的分成”，超管默认查看全部摄影师并可筛选单人；摄影师账号仅查看本人。新增摄影师在摄影师列表弹窗中完成，成功后重新请求列表。安装、验证与待确认口径见 [摄影师分成实施与验收](docs/摄影师分成实施与验收-20261111.md)。
- 摄影师建档默认由管理员填写登录账号和登录密码，保存时同步开通账号；也可选择“关联已有账号”，填写已启用的摄影师登录账号，保存后绑定系统生成的 PH 档案并保留原密码。操作见[摄影师账号同步创建](docs/摄影师账号同步创建-20261113.md)。已取消存量分成回填；清理范围及恢复方式见[摄影师分成存量清理](docs/摄影师分成存量清理-20261111.md)。
- 新增客服默认同时创建登录账号，填写账号和初始密码后自动关联本人档案；也可选择关联已有账号。操作与验证见 [客服账号直接创建](docs/客服账号直接创建-20261113.md)。
- 新增客服可自动创建或复用企业微信通讯录成员、加入客服部门并提交邀请；失败可在列表中重试。启用步骤见 [客服企微自动邀请](docs/客服企微自动邀请-20261119.md)。
- 财务管理：财务审核、月度对账。
- 系统安全：权限管理、操作日志、回收站。

## OSS 文件上传与迁移

后台素材、头像、售后凭证、成片和财务图片附件统一使用阿里云 OSS。配置字段已加入 `.env.example`；使用单私有 Bucket，公开内容保存稳定的 `/api/media/:fileId` 地址，私有文件按登录身份与订单归属换取临时读取地址。参数、RAM 权限、跨域、微信域名、上传限制及迁移操作见 [OSS 接入与迁移](docs/OSS接入与迁移.md)。

```sh
npm run oss:check
npm run migrate:files -- --schema
npm run migrate:files -- --inventory
```

截至 2026-09-17，已新增文件表且数据库健康检查通过；真实 OSS 已通过 V4 上传、私有 ACL、签名读取、匿名拒绝、防覆盖和自动清理验证。已盘点的 40 个历史引用均为 SVG 演示占位，未迁移为真实文件，也未修改其业务字段。

Linux 包默认不含 `.env`，使用 `npm run package:linux -- --name RELEASE_NAME` 生成发布包、SHA256 校验文件和可审查目录；已有同名输出会报错。以后用户说“打包后台项目”时，按 [后台发布打包规范](docs/后台发布打包规范.md)执行，包括检查、测试、打包、校验和交付说明。部署与滚动更新见 [Linux 部署说明](deploy/linux/README.md)。

## 高德地图选点

打卡点编辑页的地图选点通过运行时配置加载，源码不包含地图凭据。部署时在环境变量或部署平台密钥管理中设置 `AMAP_WEB_JS_KEY` 与 `AMAP_SECURITY_JS_CODE`；服务端会在同源 `/_AMapService` 代理中追加安全密钥，浏览器仅能读取 Web JS Key 和代理地址。也可设置 `AMAP_SERVICE_HOST=https://admin.example.com/_AMapService` 使用已有 HTTPS 反向代理，但该代理必须在服务端追加安全密钥。

高德控制台中应创建“Web端(JS API)”Key，并将后台实际访问域名加入域名白名单。请勿把 `AMAP_SECURITY_JS_CODE` 配置为浏览器端的 `securityJsCode`。

选点弹窗支持按已选城市搜索地点、地址或地标；选择搜索结果后会定位地图，并与手动地图选点一样回填 GCJ-02 坐标、详细地址和区域。

没有安装 npm 时，可以直接运行：

```powershell
node scripts/serve.cjs
```

## 当前边界

- 业务与权限数据只从真实 MySQL 读取；配置缺失或连接失败返回不可用，不回退到 JSON、演示数据或浏览器业务缓存。单进程会话可用 memory，生产/多实例使用 Redis。
- MySQL 业务表采用字段化主表和独立关系表；`npm run migrate:mysql -- --apply` 会把历史记录转换为该结构并在校验后清理旧载荷列。默认 `--dry-run` 只读统计，真实库操作前需完成备份与维护窗口确认。
- 迁移默认只处理显式配置的真实数据库，不读取 `server/data`。演示种子与 `--import-fixture` 已删除；确需导入真实历史导出时，必须显式设置 `JSON_FILE` 并传 `--import-json`，先 dry-run 审查，再执行备份及 apply。
- 已定义的业务字段不会写入整包 JSON；未预先建模的扩展值按路径拆成 `lxm_collection_values` 的 typed leaf 行，便于后续补充正式列。
- 目标 MySQL 建议使用 5.7.7+ / 8.0，并确认 InnoDB `innodb_large_prefix`（或等效 DYNAMIC 行格式）已启用，以支持关系表复合索引。
- 运行时 `DB_AUTO_MIGRATE=true` 只创建规范化表并修复少量兼容列；发现历史 `doc` 表或有数据的聚合表会直接 fail-closed，必须先执行正式迁移，避免旧载荷覆盖新数据。
- 订单异常日志的结构化快照写入 `lxm_log_order_exception_snapshots` 的明确 before/after 字段；普通日志摘要仅允许写入长度受限的 `snapshotText`。
- 回滚使用 `npm run migrate:mysql -- --rollback --confirm`，只清理本项目命名表；数据恢复必须使用已验证的数据库备份。
- 管理 API 需要 Redis Bearer 会话，菜单、角色、账号、登录凭据和数据范围均由服务端校验；前端未认证不会加载管理数据。
- 权限中心提供菜单配置、角色授权、人员新增/编辑/停用。密码只保存在 `lxm_auth_users` 的哈希字段，业务投影不保存凭据。
- 静态 HTTP 服务与发布包排除演示数据、`server/data`、测试 fixture 和项目私有文件；页面没有本地演示入口。历史本地数据文件可能包含真实业务记录，运行时不读取，且不会自动删除或导入。
- 历史 JSON 账号密码迁移必须显式传 `--file` 指定真实导出文件，默认 dry-run，写入需 `--apply`；不读取默认本地文件。财务参数使用 `financeSettings/global` 单文档。
- 微信支付及原路退款已接入小程序 JSAPI/API v3；提现与商家佣金结算不在本期直接执行。商家分成按尾款到账及每店退款窗口成熟后入账，详见 [商家分成实施与验收](docs/商家分成实施与验收-20261106.md)。

## 订单验收基线

订单流程为“已预约 → 待拍摄 → 拍摄中 → 已完成”。提交预约时先保存独立预约支付信息并支付定金，只有服务端确认到账后才创建正式预约单；取消、失败或等待到账确认期间不会生成待支付订单。客服领取、安排拍摄并登记开始拍摄；游客现场认可成片后点击尾款支付，验签回调或查单确认到账后自动完成。定金和尾款均无需财务审核，交付与附加跟进独立留痕。详见 [最新订单流程与迁移](docs/最新订单流程与迁移.md)。

微信支付的凭据、数据库迁移、回调地址和验收流程见 [微信支付接入说明](docs/微信支付接入说明.md)。

运行时只使用真实微信支付。`testPayment`、模拟支付模式和环境变量测试网关已移除；微信支付配置缺失时返回不可用。测试合成数据和提供方回调仅位于 `server/tests`，不会打包发布，也不会修改真实库。

## 真实数据库只读检查

运行 `node scripts/check-mysql-readonly.cjs`，仅执行只读事务、连接探测和表结构存在性查询，输出连接状态与缺失表名，不输出凭据，不执行建表、迁移、种子导入或业务写入。`npm test` 使用独立测试 fixture；真实 MySQL 写入型集成测试默认跳过。
